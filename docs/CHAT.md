# Чат: переписка учёного и организации

Общая память срезов 34–41 (D-214…D-216). Каждый срез чата читает этот файл целиком до работы и правит его в том же коммите, если что-то изменилось. Правила продукта меняет только пользователь; технические подробности (раздел «Контракт») закрепляет срез 34, дальше они меняются только вместе с `contracts/chat/` и тестами обеих сторон.

Образец: чат hh.ru (исследование `web-researcher` 2026-10-14: справка feedback.hh.ru, статьи hh.ru о чате 2020–2026, API hh.ru). Что взяли и что нет, ниже.

## Решения пользователя (D-214, 2026-10-14)

1. Переписка открывается только после отклика или приглашения на вакансию. Писать «в пустоту» нельзя ни учёному, ни организации.
2. В переписке только текст. Файлы по-прежнему прикладываются к отклику.
3. Статусы отклика и приглашения видны прямо в переписке отдельными системными строками, на приглашение можно ответить оттуда же. Страница отклика остаётся как есть.
4. Чат делается до модерации организаций (срез 30).

Решение D-011 («Чата нет») этим заменено.

## Правила (по умолчанию от Claude, D-215; пользователь может поменять)

**Одна переписка на пару «учёный × вакансия».** Создаётся вместе с откликом или приглашением на вакансию. Если после приглашения учёный откликнулся, переписка та же: приглашение и отклик идут в ней подряд.

**Кто участвует.**
- Со стороны учёного он сам.
- Со стороны организации все, кто вправе вести отклики этой вакансии (владелец, кадровик, руководитель её подразделения: `access.ViewApplications`). Отдельной кнопки «Добавить коллегу» нет. Права проверяются при каждом запросе: потерял роль, значит потерял доступ к переписке.
- Сообщение организации подписано именем сотрудника и названием организации.

**Кто и когда пишет.**
- После отклика писать могут обе стороны. Первой строкой идёт сопроводительное письмо (как на hh.ru).
- После приглашения на вакансию первым пишет текст приглашения. Учёный может ответить сразу, не нажимая «Интересно».
- Анонимный режим (срез 15): пока учёный не откликнулся и не ответил «Интересно», организация видит в переписке «Учёный (имя скрыто)» и ничего, по чему его легко узнать. Это касается заголовка, строки списка, системных строк, писем и уведомлений.
- Переписка закрывается для обеих сторон при отказе, отзыве отклика, ответе «Не сейчас» и отзыве приглашения. История остаётся видна, поле ввода пропадает, вместо него строка с причиной. После «Принят» переписка открыта.
- Вакансия закрыта или прошёл срок: уже открытые переписки продолжаются.

**Сообщения.**
- Текст до 4000 знаков. Без HTML и разметки, переносы строк сохраняются. Ссылки `http`/`https` кликабельны и открываются в новой вкладке с `rel="noopener noreferrer nofollow ugc"`, остальное показывается как текст.
- Галочки: одна значит «доставлено», две значат «прочитано». Сторона организации прочитала, если хоть один сотрудник открыл переписку.
- «Печатает…» видно, пока собеседник печатает.
- Своё сообщение можно исправить или удалить в течение 24 часов. Исправленное помечается «изменено», на месте удалённого собеседник видит «Сообщение удалено». На hh.ru срока нет, а удалённое пропадает без следа. Мы отошли от этого: по переписке решают судьбу человека, и история должна быть честной для обеих сторон.
- Системные строки нельзя исправить или удалить.

**Системные строки.** Отклик отправлен (с письмом), отклик просмотрен, приглашение одного из трёх видов (собеседование, контакты, просьба оставить контакты) с кнопками ответа для учёного, ответ на приглашение, отмена приглашения, решение «Принят» или «Отказ» с запиской, отзыв отклика. Для приглашения на вакансию: приглашение с текстом, «Интересно», «Не сейчас», отзыв.

**Список переписок.**
- Вкладки «Все», «Непрочитанные», «Архив». Поиск по названию вакансии и имени (имя только там, где его вправе видеть). Организации доступен отбор по вакансии.
- Строка списка: собеседник (у организации имя учёного или «имя скрыто», у учёного организация и вакансия), вакансия, состояние отклика, начало последнего сообщения, время, число непрочитанных.
- Архив личный у каждого участника. Новое сообщение возвращает переписку из архива.

**Шаблоны ответов (организация).** Общие на организацию, до 50 штук, до 4000 знаков. Править могут владелец и кадровик, вставлять все, кто ведёт отклики. Перед отправкой шаблон можно исправить.

**Защита учёного.**
- «Заблокировать организацию»: её сотрудники больше не могут писать этому учёному и звать его на вакансии. Переписки становятся только для чтения, разблокировать можно в настройках.
- «Пожаловаться»: причина (спам, обман, оскорбления, другое) и пояснение. Жалоба сохраняется для модерации (срез 30). До неё её видно только в базе.

**Уведомления.**
- В шапке пункт «Сообщения» с числом непрочитанных. Отдельно от колокольчика: сообщения в колокольчик не попадают, статусы попадают, как сейчас.
- Письмо приходит, если сообщение не прочитано 15 минут. Одно письмо на переписку, пока человек её не откроет. В письме нет текста сообщения, только кто написал и по какой вакансии, со ссылкой (почта хуже защищена, чем сайт). Письма можно выключить в настройках («Письма о новых сообщениях»).
- Новые сообщения, галочки и «печатает» появляются без перезагрузки страницы.

**Хранение.** Переписка живёт, пока жив отклик или приглашение (сроки хранения откликов ждут юриста, T-37). При удалении аккаунта учёного его переписки стираются вместе с откликами. Сообщения ушедшего сотрудника остаются за подписью «Сотрудник организации». Выгрузка своих данных включает свои переписки.

## Чего не делаем (D-216)

Файлы в переписке (D-214), звонки из чата, SMS, переписка без вакансии, массовые рассылки, реакции, отдельная кнопка «Добавить коллегу», выжимка резюме в чате (есть карточка отклика), письма с текстом сообщения.

## Контракт API (черновик, закрепляет срез 34)

Срез 34 пишет точные примеры ответов в `contracts/chat/*.json`. Тесты сайта берут из них подставные ответы, тесты сервера (срез 37 и дальше) проверяют, что настоящие ответы совпадают с ними по полям и типам. Разошлись, значит красный тест с обеих сторон.

| Метод и адрес | Что |
|---|---|
| `GET /api/chats?box=all\|unread\|archive&q=&vacancy=&cursor=&limit=` | список: `{items:[chat], next_cursor, counts:{unread, archive}}`, листание по ключу |
| `GET /api/chats/unread-count` | `{unread}` |
| `GET /api/chats/{id}` | шапка: вакансия, организация, собеседник (с учётом анонимности), `application_id`/`offer_id`, состояние, `can_write`, `closed_reason`, `viewer{side, can_use_templates, can_block}`, `read{mine, theirs}` |
| `GET /api/chats/{id}/messages?before=&after=&limit=` | `{items:[message], has_more}`; `message{id, kind: text\|system, author{side, name, is_me}, text, event{type, data}, created_at, edited_at, deleted}` |
| `POST /api/chats/{id}/messages {text, client_id}` | 201 `{message}`; `client_id` защищает от двойной отправки при повторе |
| `PATCH /api/chats/{id}/messages/{mid} {text}`, `DELETE …` | 200 / 204; 409, если прошло 24 часа или сообщение системное |
| `POST /api/chats/{id}/read {up_to}` | 204 |
| `POST /api/chats/{id}/archive`, `/unarchive` | 204 |
| `POST /api/chats/{id}/typing` | 204, не чаще раза в 3 секунды |
| `GET /api/chats/events` | живой поток событий (выбор способа в срезе 39, по умолчанию Server-Sent Events): `message.created`, `message.edited`, `message.deleted`, `chat.read`, `chat.typing`, `chat.state`, `unread.count` |
| `GET/POST/PATCH/DELETE /api/orgs/{orgId}/chat-templates[/{id}]` | шаблоны организации |
| `POST /api/chats/{id}/block`, `DELETE /api/chat-blocks/{orgId}`, `GET /api/chat-blocks` | блокировка организации учёным |
| `POST /api/chats/{id}/complaints {reason, note}` | 201 |
| `GET/PUT /api/notification-settings` | новое поле `email_messages` |
| `GET /api/applications/{id}`, `GET /api/offers/{id}` и списки | новое поле `chat_id` |

Чужая или несуществующая переписка даёт одинаковый 404, как у откликов.

## Подставной сервер (срезы 34–38)

Интерфейс строится раньше сервера. В `web/src/features/chat/mock/` живёт подставной сервер в памяти браузера: те же адреса и ответы, что в `contracts/chat/`, сам присылает «входящие» сообщения, «печатает» и галочки, чтобы живое обновление можно было проверить глазами. Включается только в режиме разработки отдельным флагом и подключается динамическим импортом. Тест сборки проверяет, что в боевой сборке его нет (T-104). Срезы 37 и 38 переводят адреса на настоящий сервер по мере готовности, срез 39 удаляет подставной сервер совсем.
