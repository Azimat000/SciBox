## [ ] 15. Анонимный режим и «скрыть от моей организации»
- Четвёртая возможность приватности для пассивного поиска: организации видят научные данные (степень, специальности, уровень, метрики, счётчики публикаций), но не имя, не место работы и не то, по чему человека легко узнать (ORCID и другие номера, названия публикаций, гранты). Имя открывается, когда учёный сам откликнулся или ответил «Интересно» на приглашение.
- «Скрыть от организаций»: учёный выбирает организации из списка, их сотрудники не видят профиль ни в каком режиме.
- Всё через пакет `privacy` (критичная зона ≥ 97%), табличные тесты на каждую пару «кто смотрит × режим × скрыт ли от него».
- Каталог, страница учёного, приглашение на вакансию: анонимная карточка («Кандидат наук, 1.4.4, R2, h-index 9»), приглашать анонима можно.
- Риски: утечка имени через снимок профиля, письма, уведомления, CV, адрес страницы; проверить все места, где профиль уходит наружу.

## [ ] 19. Периметр HTTP: таймауты, заголовки, настоящий IP, ограничение частоты, боевой режим
- `http.Server`: `ReadTimeout`, `WriteTimeout` (кроме выдачи файлов и PDF, у них свой срок), `IdleTimeout`, `MaxHeaderBytes` (T-04).
- Заголовки (T-05): CSP для сайта (без `unsafe-inline` для скриптов, если сборка Vite позволяет; иначе записать причину), `frame-ancestors 'none'`, HSTS только при https, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`. Проверка тестом на каждом виде ответа (API, страница сайта, файл, PDF).
- Настоящий IP (T-06): `SCIBOX_TRUSTED_PROXIES` (список сетей); без него заголовки прокси игнорируются, как сейчас.
- Ограничение частоты (T-07) для публичных и тяжёлых адресов: по IP для гостей, по аккаунту для вошедших; ответ 429 с `Retry-After` в формате D-032. Хранилище выбрать так, чтобы работало при двух копиях сервера (решение записать).
- Лимит тела на каждом адресе (T-09): тест проходит по всем маршрутам роутера и шлёт тело больше лимита.
- Боевой режим `SCIBOX_ENV=production` (T-08): сервер не стартует с http-адресом сайта, паролем базы по умолчанию, `sslmode=disable` к нелокальной базе, SMTP без шифрования; понятное сообщение, что исправить.
- Новый пакет `internal/httpguard` (критичная зона 97%).
- Скиллы: `golang-security`, `sharp-edges`, `golang-design-patterns`, `golang-context`, `golang-testing`.
- Готово, когда: T-04…T-09 закрыты тестами; `make share` и `make dev` работают как раньше (CSP не ломает сайт: проверить в браузере главную, поиск, профиль, отклик с файлом).
- Риски: CSP ломает шрифты или стили Vite; лимиты мешают e2e-тестам (лимиты настраиваются, в тестах свои значения).

## [ ] 20. Аккаунты и сессии: усиление
- Список своих сессий (устройство по User-Agent, примерное время) и «выйти на всех устройствах»; смена и сброс пароля завершают все другие сессии; при входе всегда новая сессия (T-10).
- Повторный ввод пароля для опасных действий: смена почты, удаление аккаунта, передача владения организацией (T-12).
- Смена почты с подтверждением нового адреса и письмом на старый; удаление аккаунта (T-11): что удаляется сразу, что обезличивается (отклики в чужих организациях), срок на отмену; решение записать (D-NNN, спросить пользователя про срок).
- Письма «вход с нового устройства» и «пароль изменён» (T-13).
- Пароль не из списка утёкших (T-14): локальный список (например, 100 000 самых частых), без отправки пароля наружу.
- Ответы регистрации и сброса не раскрывают, есть ли аккаунт (проверить и закрепить тестом).
- Интерфейс: «Настройки → Безопасность» (сессии, смена почты, удаление) по правилам impeccable.
- Скиллы: `golang-security`, `sharp-edges`, `differential-review`, `golang-testing`, `golang-database`; интерфейс: `impeccable`, `break-ui`.
- Готово, когда: T-10…T-14 закрыты; `differential-review` по срезу без открытых находок; e2e-сценарий «сменил пароль → старая сессия на другом устройстве разлогинена».
- Риски: удаление аккаунта задевает отклики, рекомендации и организации, где человек единственный владелец.

## [ ] 23. Файлы: хранилище S3, проверка на вирусы, потоковая загрузка
- Файлы откликов и рекомендаций переезжают из `bytea` в S3-совместимое хранилище (локально MinIO в `docker-compose.yml`; в бою Yandex Object Storage, Selectel или VK Cloud по настройкам). Миграция переносит существующие файлы и проверяет контрольные суммы.
- Загрузка потоком, без чтения целиком в память; проверка вида файла по содержимому до сохранения.
- Проверка на вирусы ClamAV (контейнер в `docker-compose.yml`, T-21): файл недоступен организации, пока не проверен; заражённый отклоняется с понятным сообщением.
- Выдача только через сервер с проверкой прав (как сейчас) или короткоживущей подписанной ссылкой; решение записать.
- Скиллы: `golang-security` (`filesystem.md`), `sharp-edges`, `golang-design-patterns`, `golang-concurrency`, `golang-testing`.
- Готово, когда: в базе нет содержимого файлов, T-21 закрыта, e2e «отклик с PDF» проходит, тест с файлом EICAR (тестовый «вирус») отклоняется.
- Риски: ClamAV требует ~1 ГБ памяти и обновления баз; сбой антивируса не должен ни пропускать файлы, ни терять их.

## [ ] 25. Несколько копий сервера и фоновые задачи
- Отдельная команда `worker` для фоновых задач (подбор, напоминания, письма, чистка); `serve` может работать без них. Обе безопасны в нескольких копиях (T-23): блокировки в базе, повтор не создаёт дублей.
- Повторы с нарастающей паузой, письма, которые так и не ушли, откладываются отдельно и видны в логах и метриках.
- Внешние сервисы (T-24): сроки и ограничение одновременных запросов к Crossref и SMTP, «предохранитель» при серии сбоев.
- Мягкая остановка: сервер дожидается текущих запросов, воркер возвращает взятые задачи.
- Тест: две копии `serve` и две копии `worker` на одной базе, тысяча событий → ни одного двойного письма и уведомления.
- Скиллы: `golang-concurrency`, `golang-context`, `golang-design-patterns`, `golang-troubleshooting`, `golang-testing`.
- Готово, когда: T-23, T-24 закрыты, `make dev` и `make share` запускают сервер и воркер, тест с несколькими копиями зелёный под `-race`.
- Риски: `make share` и e2e рассчитаны на один процесс (поправить скрипты).

- `Dockerfile`: многоступенчатый, итоговый образ distroless, не root, файловая система только для чтения, сайт внутри (T-27); проверка образа на уязвимости (trivy или grype).
