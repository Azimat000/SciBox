## Где остановились
Срез 9 «Разбор откликов организацией» готов. Организация видит список откликов `/candidates` (вкладки по статусам, отбор по вакансии), открывает карточку `/candidates/:id` (первое открытие ставит «просмотрен» и уведомляет соискателя), приглашает (собеседование, контакты организации, просьба оставить контакты), принимает или отказывает с запиской. Соискатель отвечает на приглашения на `/applications/:id` (подтвердить, предложить другое время, оставить контакты). Уведомления и письма обеим сторонам. В «Моих вакансиях» видно число откликов. Отчёт: `docs/slices/09-review.md`, решения D-088…D-094.

## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. Остановка: Ctrl+C.
- `make db-reset`: пересоздать базу и демо-данные (30 организаций, 216 вакансий, 17 людей, 14 профилей, 14 откликов с приглашениями). Вход: `olga.kuznetsova@demo.example.ru` (владелец Байкальского института: 8 откликов, приглашения во всех состояниях), `dmitry.korolev@demo.example.ru` (соискатель: приглашение ждёт ответа, принятый и отклонённый отклики), `alina.guseva@…` (предложила другое время), `artem.morozov@…` (просьба о контактах ждёт ответа); все `@demo.example.ru`, один пароль в `server/seed/seed.go`.
- `make test`: всё с проверкой покрытия (около 3 минут; сам поднимает Docker-контейнеры).
- Встроенный браузер Claude не запускает `make dev` из «Документов»: сервер и Vite запускать через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite --strictPort"`. Вход делать запросом `fetch('/api/auth/login', …)` через `javascript_tool`; режим «Нанимаю» включается `localStorage.setItem('scibox.role','employer')`. Для телефона `resize_window` с пресетом `mobile`, потом вернуть `desktop`.

## Известные проблемы и долги
- Не делали полный `/impeccable critique`, `/impeccable audit`, `break-ui` и `web-design-guidelines` для срезов 3, 4, 5, 7, 8, 9 и для поиска (только детектор и замеры в браузере). Всё это входит в срез 13.
- Решение по отклику окончательное (D-088): ошибочный отказ не исправить. Истории смены статусов нет. Нет поиска по имени кандидата в списке откликов, нет массовых действий. Кто отправил приглашение, не показывается (`created_by` хранится).
- Приглашение: соискатель отвечает один раз; нет напоминаний о приглашении, нет файла календаря (.ics). Время только московское (D-089).
- Вкладки статусов на телефоне занимают три строки.
- Отправленный отклик нельзя править, только отозвать и подать заново. Письмо рекомендателя нельзя заменить. Нет напоминания рекомендателю.
- Письма-уведомления нельзя отключить. «Просмотрен» тоже уходит письмом.
- Публичные адреса `/api/recommendations/*` не ограничены по IP. Файлы откликов лежат в базе (D-080), на вирусы не сканируются.
- Профиль: нет подсказки о заполненности, фото, импорта из ORCID (D-008). «Виден организациям» = любой сотрудник любой организации (D-072).
- Почта по SMTP без шифрования (только локально, D-020). Нельзя сменить почту, удалить аккаунт и организацию кнопкой (D-043, D-051).
- Запасной поиск «по похожим словам» без индекса (D-065). Заголовок вкладки всегда «SciBox».
- Текст `/privacy` черновик (нужна проверка юриста; в нём пока нет про приглашения). Тёмной темы нет. `mail` покрыт на 90,9%.
- Нет копирования вакансии и истории изменений; в списке на странице организации до 50 вакансий без листания.

## Неочевидные вещи
- Порт базы **5433** (D-028). Тесты с базой: общий помощник `internal/testkit`; в пакете `applications` помощники в `helpers_test.go` (`newWorld`, `viewedApp`, `mustInvite`, `snapshot`). Критичные зоны сервера = имена пакетов в `server/coverage.conf` (D-033).
- Права на отклики: только `access.ViewApplications` через `orgs.ActorOf` / `orgs.UsersWhoCan`; операции организации идут через `Service.staffApp` (автор отклика всегда соискатель и разбирать свой отклик не может, D-082/D-091). Таблица переходов статусов и состояний приглашений одна: `applications/transitions.go`; менять статусы можно только запросами «из ожидаемых» (`SetApplicationStatusFrom`, `SetApplicationDecision`, `MarkApplicationInvited`).
- `Service.Get` для организации **пишет**: первое открытие ставит «просмотрен». Тесты, которые открывают карточку от имени сотрудника, учитывают это.
- Уведомления: `notifications.Service.Emit(ctx, q, …)` в транзакции события; текст уведомления идёт и в письмо, переносы строк сохраняются (в колокольчике `white-space: pre-line`). Контакты соискателя в уведомления организации не кладём.
- Тесты фронтенда: `stubApi` (`web/src/test/api.ts`), фикстуры откликов и приглашений `web/src/test/applications.ts`; даты форматируются с « г.» (`3 октября 2026 г.`), время приглашений через `momentText` (МСК).
- Файлы приходят multipart (`apiSendForm`); приглашения и ответы обычным JSON.
- Записи разделов профиля: одна таблица `profile_items` с JSON; новое поле записи = `profiles.ItemFields` + `validateItem` + `web/src/features/profile/sections.ts` + `ru.ts`.
- `vacancy_view`: добавили колонку в `vacancies` — пересоздайте представление в новой миграции и `go tool sqlc generate`. sqlc: nullable `text` → `*string`, `timestamptz` в `SET x = @now` писать `@now::timestamptz`.
- Фронтенд: формы на `useForm`; данные, зависящие от того, кто смотрит, кэшируются под ключом с номером человека; `oxlint --deny-warnings` строгий (не экспортировать из файла компонента ничего, кроме компонента).
- Название продукта: `config/product.json` (D-029). Цвета и размеры только через токены; тексты только в `src/i18n/ru.ts`.
- Демо-данные детерминированы по структуре; сроки подачи считаются от дня загрузки; приглашения демо-откликов ставятся напрямую в базе (`seed/applications.go`).
