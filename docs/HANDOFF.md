# HANDOFF: записка следующей сессии

Обновлено: 2026-10-08. Срез 21 «Права доступа на каждом адресе и журнал действий» готов (`docs/slices/21-access-and-audit.md`, D-147…D-150, проверка правок `docs/slices/21-differential-review.md`). Идёт серверная очередь 18–29 (D-138), потом продуктовые 15–17.

## Где остановились
- **Журнал действий.** Таблица `audit_log` только для дописывания (триггер; можно лишь обнулить `ip`), пакет `internal/audit` (критичная зона 100%). `audit.Record(ctx, q, audit.Event{…})` пишется в транзакции действия: журнал не принял запись — действия нет (и файл отклика не выдаётся сотруднику). Адрес берётся из контекста запроса (`httpapi.recordSource`). Владелец читает журнал организации: `GET /api/organizations/{slug}/audit`, вкладка «Журнал» (`/my-organization/:slug/audit`). Личные действия аккаунта (вход, пароль, почта, удаление) пишутся без организации; экрана для них нет.
- **Таблица доступа** `cli.TestAccessTable` (`access_test.go`, строки в `access_cases_test.go`): 103 адреса × 8 видов людей. Новый адрес в роутере без строки в `accessCases()` роняет `make test`. Строка `object`: `allow` — кому можно, `deny` — что остальным (403 только с `why`, 404 и 400 с `twin`: ответ обязан совпасть с ответом на выдуманный номер).
- T-15, T-16, T-17, T-34 закрыты; новые угрозы T-35 (журнал растёт без срока хранения, срез 22) и T-36 (повторные открытия карточки не пишутся, принята).

## Как запустить
- `make dev`: база + Mailpit, миграции и справочник журналов, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. `make db-reset`: всё заново с демо-данными. Вход: `elena.orlova@demo.example.ru` (владелец, у неё есть журнал), `dmitry.korolev@demo.example.ru`, `anton.vasilev@demo.example.ru` (соискатель); пароль в `server/seed/seed.go`.
- `make share`: сайт по публичной ссылке (порт 8088, tuna или localhost.run, D-131…D-133).
- `make test`: около 7 минут. `make lint-new`: только незакоммиченные правки. `make e2e`: сквозные сценарии (база `scibox_e2e`), в срезе 21 зелёные 6/6.
- Встроенный браузер Claude не запускает `make dev` из «Документов»: сервер и Vite через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox migrate up && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f vite`. Войти в браузере можно через `fetch('/api/auth/login', …)` из `javascript_tool`.

## Неочевидные вещи
- **Новое действие в журнале:** добавить в `audit.registry` (область: организация или аккаунт), записать `audit.Record` в транзакции действия, добавить подпись в `web/src/i18n/ru.ts` (`orgs.audit.actions`; тест `TestEveryOrganizationActionHasALabelOnTheSite` читает этот файл) и тесты: запись, «отказ не пишет», «журнал недоступен — действие не проходит» (`testaudit.Break`).
- Журнал нельзя чистить в тестах: строки остаются, поэтому тесты считают записи своей организации или по действию. `testkit.Team()` сам пишет две записи `unit.head_changed`. Аккаунт, у которого есть записи журнала, нельзя удалить SQL-запросом `DELETE FROM users` (внешний ключ): в работе аккаунты стираются через `internal/erasure`.
- Таблица `TestUpDownUp` в `internal/migrate` перечисляет таблицы по миграциям: новая миграция с таблицей — новая строка и там.
- `TestEveryReferenceToTheAccountIsHandled`: ссылки на аккаунт из `audit_log` разрешены (`actor_id`, `subject_id`), адрес стирается в `erasure.Erase`.
- Приём приглашения (`orgs.accept`) берёт блокировку организации и проверяет владельца; порядок блокировок: аккаунт → организации по номеру. Новый код с блокировкой организации должен идти в том же порядке.
- Удалённый аккаунт — строка-«надгробие» (`deleted_at`, почта `deleted+<номер>@deleted`); в журнале его имя «Аккаунт удалён».
- `npx prettier` в `web/` не запускать (нет настройки, переписывает файлы). Тесты сайта при нагрузке: `npx vitest run --maxWorkers=2`.
- Порт базы **5433** (D-028). Поддельные часы в тестах с `Truncate(time.Microsecond)`. Ошибки 500 только через `apierr.WriteInternal` (D-119). Тексты сайта только в `web/src/i18n/ru.ts`. Время по Москве (D-057, D-089, D-127).
- chi называет корень поддерева по-разному: обход — `/api/vacancies/{id}/`, поиск — `/api/vacancies/{id}`.

## Известные проблемы и долги
- D-124: два почти одинаковых «Войдите…», кнопки «скоро» у входа через сервисы.
- `/api/landing` и каталоги без кеша (срез 24); каталог ищет без индекса (D-098); `OFFSET`-пагинация (срез 24).
- Файлы откликов в базе без проверки на вирусы (срез 23). Почтового сервиса для настоящих людей нет (D-131).
- Сквозные тесты не входят в CI (D-140, срез 28). Поведение tuna/localhost.run с X-Forwarded-For не проверено на живом туннеле (T-31).
- Журнал: срок хранения не выбран (T-35); личный журнал аккаунта без экрана; адрес владельцу не показывается.
- В тестах сайта предупреждение React о повторяющемся ключе (`offers.test.tsx`), тест зелёный.
