# HANDOFF: записка следующей сессии

Обновлено: 2026-10-09. Срез 23 «Файлы: хранилище S3, проверка на вирусы, потоковая загрузка» готов (`docs/slices/23-files-storage.md`, D-157…D-160). Идёт серверная очередь 18–29 (D-138), потом продуктовые 15–17. `ТЕКУЩИЙ: 24` (база данных под объём «вся наука РФ»).

## Где остановились
- **Файлы в S3.** `blobstore.Store` (боевая реализация `S3` на minio-go, `Memory` для тестов), склад `files.Vault` (приём потоком: PDF по первым байтам до записи, SHA-256, проверка ClamAV). Сервисы `applications` и `references` принимают уже записанные `files.Stored` и сами забирают их при известном отказе до записи в базу (`knownRefusal`); при сбое базы файлы не трогают (их уберёт чистка).
- **Проверка на вирусы.** Вирус найден: 422 с названием файла, объекта нет. Антивирус недоступен: файл `pending`, никому не выдаётся; фоновая задача `filework` (раз в 30 с) проверяет с паузой 30 с … 1 ч. Найденный позже: `infected`, ключ стёрт, объект удалён, уведомление `file_rejected`.
- **Миграция 00019.** `data` переименован в `legacy_data` и больше не заполняется (ограничение `application_files_no_content`); старые файлы `filework` переносит сам при первом проходе (сверка SHA-256). Столбец `legacy_data` удалить в срезе 28 (после выкладки). Стирание аккаунта кладёт ключи в `blob_deletions`, объекты удаляет `filework`.
- **Часть `data` в multipart идёт первой**, поля проверяются до файлов (`files.Decode(..., check)`); сайт так и отправляет.
- **Старые долги из HANDOFF 22 остались**: политика `/privacy` черновик (добавлена фраза про антивирус), выгрузка собирается Blob в браузере (SCALING), `break-ui` и `impeccable audit` по блоку «Ваши данные» не делались.

## Как запустить
- `make dev`: база, почта, **хранилище файлов (порт 8333) и ClamAV (3310)**, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. `make db-reset`: всё заново с демо-данными. Вход: `elena.orlova@demo.example.ru` (владелец), `dmitry.korolev@demo.example.ru` (соискатель с откликами и файлами); пароль в `server/seed/seed.go`.
- Если контейнеры не поднимаются: `docker compose ps`; Docker Desktop должен иметь не меньше 4 ГБ памяти (облегчённый ClamAV занимает ~1 ГБ, полный не помещается: D-158).
- `make test`: около 8 минут (линтер, vulncheck, сервер с порогами, сайт), `make lint-new`, `make e2e` (6 сценариев, включая EICAR и PDF).
- Встроенный браузер Claude не запускает `make dev` из «Документов»: сервер и Vite через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox migrate up && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f vite`. Войти: `fetch('/api/auth/login', …)` из `javascript_tool`.

## Неочевидные вещи
- MinIO удалён с Docker Hub и Quay (сентябрь 2026): локальное хранилище SeaweedFS 4.48. Оно само создаёт бакет при записи (настоящий S3 так не делает): случай «бакет пропал» проверяет подставной S3-сервер.
- Тесты хранилища и антивируса падают (не пропускаются), если контейнеры не подняты: `make db-up`. Тесты `cli` создают свой бакет `t-cli-…` и удаляют его; `make e2e` использует бакет `scibox-e2e`, рабочий сервер `scibox-files`. **Один бакет на две базы нельзя**: чистка осиротевших удалит чужие объекты (защита: отказ при >20 «сирот» и >10%).
- Облегчённый ClamAV ловит только EICAR (`docker/clamav-dev/eicar.ndb`, подпись по телу). Настоящую заражённую сигнатуру и полные базы проверить при выкладке (T-41).
- Новые коды: 409 `file_pending`, 503 `storage_unavailable`; у файла в ответе поле `scan` (`clean|pending|infected`).
- `testkit.World` теперь несёт `Store` (память), `AV` (подставной, находит EICAR), `Vault`, помощники `w.PDF(имя)` и `w.Stored(имя, байты)`. Любой новый сервис с файлами берёт `*files.Vault`.
- Тесты `filework` начинают с чистки `application_files`, `blob_deletions`, `notifications`, `outbox` (проход берёт всё из базы пакета).
- `go.mod`: `toolchain go1.26.9`, добавлен minio-go v7.3.0 (август 2026) и его зависимости. `npx prettier` в `web/` не запускать. Порт базы **5433**. Ошибки 500 только через `apierr.WriteInternal`. Тексты сайта только в `web/src/i18n/ru.ts`. Время по Москве.

## Известные проблемы и долги
- T-41 (полный ClamAV), T-43 (шифрование и закрытость бакета у провайдера), T-44 (метрики очереди проверки): `docs/SECURITY.md`.
- Выдача файлов идёт через сервер (D-157): при большой нагрузке упрётся в сеть сервера (SCALING, срез 27).
- Сквозные тесты не входят в CI (D-140, срез 28). В `ci.yml` добавлен шаг `docker compose up -d --wait s3 clamav` перед тестами сервера (тестам нужны хранилище и ClamAV); на GitHub это не прогонялось (отправка только с разрешения пользователя). Поведение tuna/localhost.run с X-Forwarded-For не проверено (T-31).
- D-124: два почти одинаковых «Войдите…», кнопки «скоро» у входа через сервисы.
- Процесс `./bin/scibox serve` (PID 89174), запущенный до этой сессии, оставлен как был; он на старом коде без хранилища.
