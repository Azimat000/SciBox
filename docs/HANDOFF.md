## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. Остановка: Ctrl+C.
- `make db-reset`: пересоздать базу и загрузить демо-данные (организации, подразделения, 9 людей). Вход: `elena.orlova@demo.example.ru` (владелец Сибирского института), `pavel.sokolov@…` (кадровик), `marina.zaitseva@…` (руководитель лаборатории), `anton.vasilev@…` (без организации, ему пришло приглашение); все `@demo.example.ru`, один пароль, записан в `server/seed/seed.go`.
- `make test`: всё с проверкой покрытия (сам поднимает Docker-контейнеры). Docker Desktop должен быть запущен.
- Встроенный браузер Claude не запускает `make dev` из «Документов»: запускать сервер и Vite через Bash в фоне (`go build -o bin/scibox ./cmd/api` и `npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite --strictPort"`.

- Письма уходят в фоне и не переживают падение сервера (нет очереди). Для писем-уведомлений в срезе 8 нужен «outbox»; приглашения в организацию тоже (сейчас ссылку можно отправить заново кнопкой).
- Почта по SMTP без шифрования (только локально, D-020); IP для ограничений берётся из соединения (за прокси нужен доверенный заголовок).
- Нельзя сменить почту, удалить аккаунт и организацию кнопкой (D-043, D-051): срез 7 и позже.
- Нельзя передать владение, кроме как сделать второго владельца и понизить первого. Отклонить приглашение нельзя (оно истекает через 7 дней).
- Нет: `/impeccable critique` и `web-design-guidelines` по экранам срезов 3 и 4 (были снимки и ручные проверки, `break-ui` и детектор по срезу 4). Сделать в срезе 6 вместе с поиском.
- Текст `/privacy` — черновик; про организации в нём пока ничего нет (имена руководителей публичны): дополнить вместе с юристом.
- Тёмной темы нет. `mail` покрыт на 90,9%.

## Неочевидные вещи
- Порт базы **5433** (D-028). Тесты с базой: `testdb.New(t)` / `testdb.Create(t, migrated)`; пакеты `auth` и `orgs` берут одну базу на весь пакет (`main_test.go`), тесты берут уникальные почты и названия. Критичные зоны сервера = имена пакетов в `server/coverage.conf` (D-033).
- `orgs.Service` принимает интерфейс `DB`: `fault_test.go` ломает n-й запрос в каждой операции. Новую операцию добавлять в `TestDatabaseFailuresAreNeverSwallowed`.
- Данные, зависящие от того, кто смотрит (права, номера руководителей), кэшируются на фронтенде под ключом с номером человека (`keys` в `features/orgs/api.ts`), и запросы ждут `useMe()`.
- Страницы для вошедших оборачиваются в `RequireUser` (`features/orgs/RequireUser.tsx`); без входа ведёт на `/login?next=…` (адрес кодируется).
- Приглашение принимается одним запросом: «погасить» + стать сотрудником в одной транзакции; чужая почта откатывает всё, ссылка остаётся живой.
- Сервер ждёт JSON с `Content-Type: application/json` на всех запросах, меняющих данные, даже без тела (`apiSend` шлёт `{}`).
- Название продукта меняется в одном месте: `config/product.json` (D-029). Все цвета и размеры только через токены; тексты только в `src/i18n/ru.ts`. `oxlint --deny-warnings` строгий (`only-export-components`: функции-помощники не рядом с компонентами).
- sqlc: nullable `text` → `*string` (переопределение в `sqlc.yaml`).
