# HANDOFF: записка следующей сессии

Обновлено: 2026-10-03, после среза 8.

## Где остановились
Срез 8 «Отклик и рекомендательные письма» готов. Учёный откликается на вакансию (`/vacancies/:id/apply`): профиль уходит снимком, плюс письмо, PDF-файлы, резюме из профиля и до трёх рекомендателей. Рекомендатель получает письмо с одноразовой ссылкой и пишет по ней без аккаунта (`/recommend?token=`). «Мои отклики» (`/applications`), отклик соискателя (`/applications/:id`, письма рекомендателей он не видит), минимальная карточка для организации (`/candidates/:id`, письма видны). Колокольчик в шапке и `/notifications`; все уведомления дублируются письмом через очередь `outbox`. Отчёт: `docs/slices/08-applications.md`, решения D-079…D-087.

## Что дальше
Срез 9 «Разбор откликов организацией» (`docs/ROADMAP.md`): список откликов по вакансии, статусы, приглашения трёх видов, уведомления обеим сторонам.
- Что уже есть: таблица `applications` (статусы `sent|viewed|invited|rejected|accepted|withdrawn`), карточка `/candidates/:id` (там можно ставить кнопки), `applications.Service.Get` отдаёт её по правам `access.ViewApplications` (через `orgs.ActorOf`), `notifications.Service.Emit(ctx, q, Notice{...})` создаёт уведомление и письмо в транзакции события, `orgs.UsersWhoCan` отвечает «кому сообщить».
- Что нужно: таблица допустимых переходов для организации (отправлен → просмотрен → приглашение → отказ/принят; запрос `SetApplicationStatusFrom` защищает от гонок, отзыв соискателя уже сделан), список откликов (пункт меню «Отклики» ведёт на `/candidates`, там пока заглушка), число откликов на «Мои вакансии», приглашения (собеседование: дата, время, ссылка или адрес; контакты; просьба оставить контакты), автоматическое «просмотрен» при открытии карточки.
- Приглашения и ответы соискателя новая критичная зона `applications` (порог 97%); таблицы «кто → что» уже есть как образец (`TestWhoSeesTheApplication`, `TestFileAccess`).

## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. Остановка: Ctrl+C.
- `make db-reset`: пересоздать базу и загрузить демо-данные (30 организаций, 216 вакансий, 17 людей, 14 профилей, 14 откликов). Вход: `dmitry.korolev@demo.example.ru` (5 откликов во всех статусах, рекомендации во всех состояниях), `elena.orlova@demo.example.ru` (владелец организаций, в колокольчике отклики), `olga.kuznetsova@…` (кадровик), `ksenia.lebedeva@…`, `roman.shiryaev@…` (скрытый профиль, но откликался); все `@demo.example.ru`, один пароль в `server/seed/seed.go`.
- `make test`: всё с проверкой покрытия (сам поднимает Docker-контейнеры; серверные тесты идут около 2 минут).
- Встроенный браузер Claude не запускает `make dev` из «Документов»: сервер и Vite запускать через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite --strictPort"`. Вход делать запросом `fetch('/api/auth/login', …)` через `javascript_tool`. Скриншоты при эмуляции 1440 ломаются (виден кусок страницы): для компьютера брать ширину 1100–1160, для телефона 375×812; размеры мерить через `javascript_tool`.

## Известные проблемы и долги
- Не делали полный `/impeccable critique` и `web-design-guidelines` для срезов 3, 4, 5, 7, 8 и для поиска (только детектор и замеры в браузере). Проверка худших данных в срезе 8 сделана вручную в браузере (длинные названия, имена и почты), не навыком `break-ui`.
- Нет автоматического «просмотрен» и списка откликов у организации (срез 9). Карточка `/candidates/:id` открывается только по ссылке из уведомления.
- Отправленный отклик нельзя править, только отозвать и подать заново. Письмо рекомендателя нельзя заменить после отправки. Нет напоминания рекомендателю, если он молчит.
- Письма-уведомления нельзя отключить. Время в окнах показывается по часовому поясу браузера.
- Публичные адреса `/api/recommendations/*` не ограничены по IP (ссылка 256-битная, подбор невозможен, но каждый неверный токен стоит запрос в базу).
- Файлы откликов лежат в базе (D-080), PDF проверяется только по метке `%PDF-`, на вирусы и структуру не сканируется. Для публикации в интернет пересмотреть.
- Профиль: нет подсказки о заполненности, нет фото, нет импорта из ORCID (D-008), нет проверки, что ORCID принадлежит человеку. «Виден организациям» = любой сотрудник любой организации (D-072).
- Почта по SMTP без шифрования (только локально, D-020). Нельзя сменить почту, удалить аккаунт и организацию кнопкой (D-043, D-051).
- Запасной поиск «по похожим словам» без индекса (D-065). Поиск: нет подсказок при наборе слова, нет подсветки, заголовок вкладки всегда «SciBox».
- Текст `/privacy` черновик (в срезе 8 добавлено про профиль и отклики, нужна проверка юриста). Тёмной темы нет. `mail` покрыт на 90,9%.
- Справочники: коды регионов и номера документов для должностей сверены вторичными источниками (`docs/REFERENCE.md`).
- Нет копирования вакансии и истории изменений; в списке на странице организации до 50 вакансий без листания.

## Неочевидные вещи
- Порт базы **5433** (D-028). Тесты с базой: общий помощник `internal/testkit` (`testkit.RunMain(m)` в `TestMain`, `NewWorld`, `Team`, `Published`, `Applicant`, `RunFaults`, `NewAPI`). Старые пакеты (`auth`, `orgs`, `vacancies`, `profiles`) пользуются своими помощниками (пакеты не могут импортировать `testkit`: цикл). Критичные зоны сервера = имена пакетов в `server/coverage.conf` (D-033).
- Права на отклики: только `access.ViewApplications` через `orgs.ActorOf` / `orgs.UsersWhoCan`; автор отклика всегда соискатель (D-082). Что видит каждый вид файла: `files.Kind.VisibleTo`. В ответе соискателю рекомендательных писем нет вовсе: у `references.Request` нет поля письма, у `references.StaffRequest` оно есть, не смешивать.
- Приватность профиля: через `privacy.Visibility.CanView/CanSeeContacts` и `profiles.Service.build`. Отклик идёт другим явным путём `profiles.Service.ForApplication` (снимок + резюме, без проверки режима).
- Письма: никто не шлёт письма напрямую. `auth` и `orgs` получают `notifications.Queue` (поставить в очередь), уведомления делает `notifications.Service.Emit(ctx, q, …)` внутри транзакции события, письма на чужой адрес (рекомендатель) `Service.Enqueue`. Отправитель `notifications.Worker` стартует в `cli.serve`. В тестах письма проверять по таблице `outbox` (например `SELECT … FROM outbox WHERE to_email = …`).
- Файлы приходят multipart: часть `data` (JSON) и части `file`; на сайте `apiSendForm`, в тестах `stubApi` разбирает форму (в теле `__files` — имена файлов). Проверка Origin защищает такие запросы так же, как JSON.
- Записи разделов профиля: одна таблица `profile_items` с JSON; новое поле записи = поле в `profiles.ItemFields` + проверка в `validateItem` + `web/src/features/profile/sections.ts` + подписи в `ru.ts`.
- `vacancy_view`: `v.*` раскрывается при создании; добавили колонку в `vacancies` — пересоздайте представление в новой миграции и `go tool sqlc generate`.
- «Сегодня» для сроков = Москва (`Service.today()` в `vacancies` и `applications`), последний день включительно. Часы в сервисах подменяются полем `now`.
- `stubApi` (`web/src/test/api.ts`): ключ маршрута, оканчивающийся на `*`, отвечает на любой адрес с таким началом. Фикстуры откликов: `web/src/test/applications.ts`.
- Фронтенд: формы на `useForm`; данные, зависящие от того, кто смотрит, кэшируются под ключом с номером человека; страницы для вошедших в `RequireUser`; `oxlint --deny-warnings` строгий (не экспортировать из файла компонента ничего, кроме компонента; не создавать компоненты внутри рендера).
- Название продукта меняется в одном месте: `config/product.json` (D-029). Цвета и размеры только через токены; тексты только в `src/i18n/ru.ts`. Форматирование: prettier без точек с запятой, одинарные кавычки, ширина 160 (в проекте не настроен; не форматировать чужие файлы целиком).
- sqlc: nullable `text` → `*string`, `smallint` → `*int16`, `integer` → `*int32`, `date` → `time.Time`; для `timestamptz` в `SET x = @now` писать `@now::timestamptz`, иначе получится указатель.
- Демо-данные детерминированы по структуре; сроки подачи считаются от дня загрузки; профили и отклики загружаются через сервисы (после основной транзакции).
