## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. Остановка: Ctrl+C.
- `make db-reset`: пересоздать базу и загрузить демо-данные (организации, подразделения, 9 людей, 26 вакансий). Вход: `elena.orlova@demo.example.ru` (владелец Сибирского института), `pavel.sokolov@…` (кадровик), `marina.zaitseva@…` (руководитель лаборатории в институте квантовых материалов и кадровик в Южном институте морской биологии), `anton.vasilev@…` (без организации, ему пришло приглашение); все `@demo.example.ru`, один пароль, записан в `server/seed/seed.go`.
- `make test`: всё с проверкой покрытия (сам поднимает Docker-контейнеры). Docker Desktop должен быть запущен.
- Встроенный браузер Claude не запускает `make dev` из «Документов»: запускать сервер и Vite через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite --strictPort"`. Поля форм в браузере удобно заполнять через `javascript_tool` (родной установщик значения + событие `input`).

## Известные проблемы и долги
- Письма уходят в фоне и не переживают падение сервера (нет очереди). Для писем-уведомлений в срезе 8 нужен «outbox»; приглашения в организацию тоже.
- Почта по SMTP без шифрования (только локально, D-020); IP для ограничений берётся из соединения (за прокси нужен доверенный заголовок).
- Нельзя сменить почту, удалить аккаунт и организацию кнопкой (D-043, D-051): срез 7 и позже. Нельзя передать владение, кроме как сделать второго владельца и понизить первого. Отклонить приглашение нельзя.
- Нет: `/impeccable critique` и `web-design-guidelines` по экранам срезов 3, 4 и 5 (были снимки, детектор, `break-ui`, ручные проверки).
- Текст `/privacy` — черновик; про организации и вакансии в нём ничего (имена руководителей публичны).
- Тёмной темы нет. `mail` покрыт на 90,9%.
- Справочники: коды регионов (основные автомобильные) и номера документов для должностей сверены вторичными источниками, по первоисточнику не проверялись (`docs/REFERENCE.md`). Если появится способ открыть pravo.gov.ru, сверить специальности ВАК с официальным PDF.
- У справочных специальностей нет статуса «действует»: если специальность отменят, а вакансии на неё есть, придётся добавить колонку (см. REFERENCE.md).
- Нет копирования вакансии («создать похожую») и истории изменений; в списке на странице организации до 50 вакансий без листания (пока не поместившиеся видны в поиске, срез 6).

## Неочевидные вещи
- Порт базы **5433** (D-028). Тесты с базой: `testdb.New(t)` / `testdb.Create(t, migrated)`; пакеты `auth`, `orgs` и `vacancies` берут одну базу на весь пакет (`main_test.go`), тесты берут уникальные почты и названия. Критичные зоны сервера = имена пакетов в `server/coverage.conf` (D-033; `vacancies` добавлен в срезе 5).
- Права на вакансии: только `access.ManageVacancies` через `orgs.ActorOf`; в SQL ролей нет. Для «Мои вакансии» сервис собирает `wholeOrgs` и `units` по `Can`, и запрос лишь фильтрует по ним.
- `vacancy_view`: `v.*` раскрывается при создании; добавили колонку в `vacancies` — пересоздайте представление в новой миграции (и `go tool sqlc generate`).
- Опечатки в названиях специальностей лечить новой миграцией, не правкой 00004.
- Формы: значения полей названы как поля сервера (`position_code`, `work_format`…), поэтому ошибки сервера (`fields`) попадают в нужное поле сами. Создание и публикация одной кнопкой: если публикация не прошла, черновик уже создан, и повторная отправка правит его (ссылка `created` в `VacancyEditPage`).
- «Обязательно» на полях формы показано только у названия и должности: остальное нужно для публикации, об этом говорит строка над формой и ответ сервера при публикации.
- Данные, зависящие от того, кто смотрит (права, черновики), кэшируются на фронтенде под ключом с номером человека (`keys` в `features/orgs/api.ts`, `features/vacancies/api.ts`), запросы ждут `useMe()`.
- Страницы для вошедших оборачиваются в `RequireUser` (`features/orgs/RequireUser.tsx`); без входа ведёт на `/login?next=…`.
- Сервер ждёт JSON с `Content-Type: application/json` на всех запросах, меняющих данные, даже без тела (`apiSend` шлёт `{}`) и со своего адреса (`Origin`).
- Название продукта меняется в одном месте: `config/product.json` (D-029). Все цвета и размеры только через токены; тексты только в `src/i18n/ru.ts`. `oxlint --deny-warnings` строгий (`only-export-components`: функции-помощники не рядом с компонентами, поэтому `formValues.ts` отдельно от `VacancyForm.tsx`).
- sqlc: nullable `text` → `*string`, `smallint` → `*int16`, `integer` → `*int32`, `date` → `time.Time` (переопределения в `sqlc.yaml`).
- Агент `web-researcher` не открывает pravo.gov.ru и КонсультантПлюс; текстовые страницы «Гарант» (`base.garant.ru`) обычная загрузка отдаёт целиком.
