# HANDOFF: записка следующей сессии

Обновлено: 2026-10-08. Срез 20 «Аккаунты и сеансы» готов (`docs/slices/20-account-security.md`, D-142…D-146, проверка правок `docs/slices/20-differential-review.md`). Идёт серверная очередь 18–29 (D-138), потом продуктовые 15–17.

## Где остановились
- `auth`: список сеансов и завершение любого; свежий пароль на 10 минут (`Principal.Fresh`, `POST /api/account/reauth`, ответ 403 `reauth_required`); смена почты со ссылкой «это не я» на старый адрес; удаление аккаунта с 14 днями на отмену, стирание в фоновой уборке; письмо «вход с нового устройства» (cookie `scibox_device`); список частых паролей NCSC в `internal/auth/data`.
- Новый пакет `internal/erasure` (критичная зона): что стирается, что обезличивается, «единственный владелец». Тест `TestEveryReferenceToTheAccountIsHandled` упадёт, если новая таблица ссылается на `users` без правила стирания: тогда дописать шаг в `erasure.Erase` (или в список разрешённых ссылок «кто сделал»).
- `orgs.ChangeRole` и `orgs.Invite` принимают `auth.Principal`: роль владельца только со свежим паролем.
- Сайт: вкладки «Аккаунт» / «Безопасность» (`/account/security`), окно пароля `ReauthProvider` + `useReauth` (оборачивать любой запрос, на который сервер может ответить `reauth_required`), страницы `/confirm-email-change`, `/revert-email-change`, полоса `DeletionBanner`.
- T-10…T-14 закрыты; инварианты I-25…I-29; новые угрозы T-32 (откат почты взломщиком старого ящика, принята), T-33 (остатки в уведомлениях и `outbox` после стирания, срез 22), T-34 (организация без владельца при гонке, срез 21).

## Как запустить
- `make dev`: база + Mailpit, миграции и справочник журналов, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. `make db-reset`: всё заново с демо-данными. Вход: `elena.orlova@demo.example.ru`, `dmitry.korolev@demo.example.ru`, `anton.vasilev@demo.example.ru` (соискатель); пароль в `server/seed/seed.go`.
- `make share`: сайт по публичной ссылке (порт 8088, tuna или localhost.run, D-131…D-133).
- `make test`: около 6 минут. `make lint-new`: только незакоммиченные правки. `make e2e`: сквозные сценарии (база `scibox_e2e`), в срезе 20 зелёные 6/6.
- Встроенный браузер Claude не запускает `make dev` из «Документов»: сервер и Vite через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox migrate up && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite"`.

## Неочевидные вещи
- Демо-люди входят по паролю, поэтому сразу «свежие»; сеанс после подтверждения почты — нет (окно пароля появится).
- Удалённый аккаунт — строка-«надгробие» (`deleted_at`, почта `deleted+<номер>@deleted`), а не удалённая строка: на неё ссылаются обезличенные отклики. Запросы, которые ищут людей по почте или для входа, должны учитывать `deleted_at`.
- Фоновое стирание идёт в `auth.Cleanup` раз в час; в тестах вызывать `ProcessDueDeletions`, сдвинув `deletion_due_at` в прошлое SQL-запросом.
- `npx prettier` в `web/` не запускать: в проекте нет его настройки, он переписывает файлы с точками с запятой.
- Тесты сайта при сильной загрузке Mac падают с «Timeout waiting for worker»: `npx vitest run --maxWorkers=2`.
- chi называет корень поддерева по-разному: обход — `/api/vacancies/{id}/`, поиск — `/api/vacancies/{id}`. Периметр сравнивает без конечной черты.
- Порт базы **5433** (D-028). Поддельные часы в тестах с `Truncate(time.Microsecond)`. Ошибки 500 только через `apierr.WriteInternal` (D-119). Тексты сайта только в `web/src/i18n/ru.ts`. Время по Москве (D-057, D-089, D-127).
- Скилл `golang-security` и другие `golang-*` подхватываются по путям файлов; если `Skill` его не видит, прочитать `.claude/skills/golang-security/SKILL.md` напрямую.

## Известные проблемы и долги
- D-124: два почти одинаковых «Войдите…», кнопки «скоро» у входа через сервисы.
- `/api/landing` и каталоги без кеша (срез 24); каталог ищет без индекса (D-098); `OFFSET`-пагинация (срез 24).
- Файлы откликов в базе без проверки на вирусы (срез 23). Почтового сервиса для настоящих людей нет (D-131).
- Сквозные тесты не входят в CI (D-140, срез 28). Поведение tuna/localhost.run с X-Forwarded-For не проверено на живом туннеле (T-31).
- В тестах сайта предупреждение React о повторяющемся ключе (`offers.test.tsx`), тест зелёный.
