## Где остановились
- **Сервер умеет переписки**: `server/internal/chat`, миграция `00031_chat.sql`, адреса `/api/chats…` (список, числа, вакансии для отбора, шапка, лента, отправка, правка, удаление, прочтение, архив, «печатает» как проверка прав). Контракт сверяется тестом `chat.TestHTTPFollowsTheContract`.
- **Переписок пока никто не создаёт**: `chat.Open` и `chat.AppendSystem` готовы, но отклики и приглашения их ещё не вызывают (это срез 38). Без демо-данных настоящий список пуст; для проверки руками переписку вставляют через `chat.Open` или SQL.
- **Сайт без изменений**: без флага `VITE_CHAT_MOCK=1` он говорит с настоящим сервером, шаблоны, блокировки, жалобы и поток дают 404 (сайт это переживает, D-228). С флагом работает подставной сервер как раньше.
- **Что ждёт пользователя вне кода**: хостинг и `docs/DEPLOY.md` (раздел 11); модерация (срез 30, туда же жалобы из чата); юрист: сроки хранения откликов (T-37), `/privacy` (T-89); запуск `/review-animations` по `chat-window.css` и `chat-tools.css`.

## Что дальше: 38
- Прочитать `docs/CHAT.md` (раздел «Сервер (срез 37)»), раздел 38 в ROADMAP, `docs/SECURITY.md` (T-97, T-103, T-105, T-107), `docs/SCALING.md`. Скиллы: `golang-how-to`, `use-modern-go`, `golang-refactoring`, `golang-design-patterns`, `golang-database`, `golang-security`, `golang-testing`, `differential-review`.
- **Вызов из откликов и приглашений**: в транзакции события `chat.Open(ctx, q, OpenInput, now)`, затем `chat.AppendSystem(ctx, q, chatID, тип, данные, now)`. Круга импортов нет: `chat` не импортирует `applications` и `offers`. Данные строки о событии должны совпадать с примерами `contracts/chat/messages.json` и не содержать имён и почт (T-97). Закрытие переписки считает `chat.StateOf` по статусам; блокировку добавлять туда же (D-229).
- **Порядок замков (D-230)**: отклик или приглашение, потом переписка, потом личные отметки. Решение организации (`applications`) должно брать их так же, иначе отправка и закрытие подерутся.
- Перенос прежних откликов и приглашений: разовая команда (`Open` + первая строка о событии с `created_at` отклика).
- `chats.org_id` записывается из вакансии при `Open`: другой организацией вакансия не станет.

- `make dev` (сайт http://localhost:5173, сервер 8080). Чат на подставном сервере: `VITE_CHAT_MOCK=1 make dev`, вход `elena.orlova@demo.example.ru` и `dmitry.korolev@demo.example.ru`, пароль в `server/seed/seed.go`.
- `make test` (≈20 минут), `make lint-new`, `make vulncheck`, `make e2e`; `npm run lint`, `npm run typecheck` в `web/`.
- Объёмные данные: `scripts/load-data 0.1` (7–8 минут, около 2 ГБ; на диске после срезов 36–37 осталось около 5 ГБ, масштаб 1 не влезет). `scibox_load` пересоздаётся и после замеров удаляется: `DROP DATABASE scibox_load WITH (FORCE)`.

## Неочевидные вещи
- **Список организации идёт двумя запросами** (организации целиком и подразделения руководителя) и сливается в Go (`chat/list.go`): так каждая ветка читает первую страницу по индексу. Пустая ветка передаётся как `NULL`.
- **Страница списка выбирается подзапросом `page`** только по дешёвым условиям, подробности и «открыл ли имя» считаются для 30 строк. Не добавлять в `page` соединения «на всякий случай»: планировщик возвращается к чтению всех переписок (замерено, 190 мс против 5 мс).
- **Номер сообщения в ответе** (`id`) выводится из номера переписки и `seq` (UUID v5), в базе не лежит.
- **Удаление стирает текст** (D-232).
- **«Печатает»** пока только проверка прав: рассылка в 39 вместе с потоком.
- **`TestReadArchiveAndSendDoNotDeadlock`** не воспроизвёл взаимную блокировку при прежнем порядке замков (рассуждение, не опыт); порядок в `MarkRead` зафиксирован комментарием.
- Прежние: состояние приглашения считается по строкам ленты (`events.ts`); `useArchive.ts` отдельным файлом; зона покрытия сайта `'src/features/chat/*.{ts,tsx}'`; на iCloud файлы проекта выгружаются (`dataless`), лечится `find web server deploy config -type f -flags +dataless -exec cat {} +`; зависимости сайта в `web/node_modules.nosync`; порт базы 5433; `preview_start` падает («getcwd»), `make dev` из терминала; `npx prettier` в `web/` не запускать; тексты только в `web/src/i18n/ru.ts`.

## Известные проблемы и долги
- Чат: T-97 частично (строки о событиях, уведомления, письма в 38), T-98 письмо в 39 и итог в 40, T-103 выгрузка в 38, T-104 подставной сервер удаляется в 39, T-107 права шаблонов в 38; T-99, T-100, T-102, T-105 открыты по плану.
- Числа вкладок и «Вакансии для отбора» читают все переписки организации: у лидера масштаба 1 около 30 тысяч (8 мс при 3 тысячах). Если станет заметно: число непрочитанных рядом с отметкой чтения (`docs/SCALING.md`).
- В окне переписки на компьютере страница прокручивается, если окно ниже экрана; `touch-action: manipulation` нигде не задан; шапка при увеличении текста ×2 налезает на меню; `OfferPage.tsx` `onSubmit` без теста. Всё было до чата.
- Не сделано: цель 500 зап/с на боевой машине; ClamAV полный и Let's Encrypt (T-41); повтор удалений после восстановления (T-55); образы по хэшам (T-56); действия GitHub кроме trivy на тегах (D-219); `legacy_data`; поиск навыков по раскладке; D-124; e2e не в CI (D-140); `files.sweep` в dev ругается на общий бакет.
