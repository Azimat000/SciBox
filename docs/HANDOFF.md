# HANDOFF: записка следующей сессии

Обновлено: 2026-10-09. Срез 22 «Персональные данные и 152-ФЗ» готов (`docs/slices/22-personal-data.md`, D-151…D-153). Идёт серверная очередь 18–29 (D-138), потом продуктовые 15–17. `ТЕКУЩИЙ: 23` (файлы: хранилище S3, проверка на вирусы, потоковая загрузка).

## Где остановились
- **Логи без ПДн.** `internal/logmask` (критичная зона) оборачивает любой `slog.Handler`; логгер создаётся только в `cli.newLogger`, `cli.Run` делает его журналом по умолчанию (и для стандартного `log`). Тест `TestNoLoggerBypassesTheMask` ищет в исходниках любой другой способ писать в журнал: новый логгер в обход упадёт в `make test`. Имена людей в журнале маска не узнаёт: в записи только номера.
- **Сроки хранения.** `internal/retention` раз в час (и при старте): уведомления 90 дней / год, журнал 3 года, адрес в журнале 180 дней, регистрации без почты 7 дней. Сроки лежат в `retention.DefaultPolicy`, ниже полов не опускаются. Журнал удаляется только внутри транзакции с `scibox.audit_purge` и только записи старше 90 дней (триггер, миграция 00018). Текст отправленного письма стирается сразу (`MarkOutboxSent`).
- **Выгрузка.** `GET /api/account/export` (`internal/dataexport`): ZIP, свежий пароль, 3 в сутки, запись `account.data_exported`. Новая таблица с данными человека: добавить раздел в `dataexport.sections()`, строку в карту ПДн (`docs/SECURITY.md`, тест сверки с таблицами базы) и шаг в `erasure.Erase`.
- **Удаление аккаунта** проверено по всем таблицам (`cli.TestErasedPersonLeavesNothingToRecogniseThemBy`); исправлены остатки: уведомления об ответах на приглашения (теперь ссылка `/sent-offers?offer=<номер>`) и история писем рекомендателям.
- T-18, T-19, T-20, T-33, T-35 закрыты. Новые: T-37 (отклики без срока, вопрос юристу), T-38 (неактивные аккаунты), T-39 (письма третьим лицам после удаления), T-40 (резервные копии, срез 28).

## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. `make db-reset`: всё заново с демо-данными. Вход: `elena.orlova@demo.example.ru` (владелец), `dmitry.korolev@demo.example.ru` (соискатель с откликами и файлами); пароль в `server/seed/seed.go`.
- `make test`: около 7 минут, `make lint-new` только правки, `make vulncheck`, `make e2e` (сквозные сценарии).
- Встроенный браузер Claude не запускает `make dev` из «Документов»: сервер и Vite через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox migrate up && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f vite`. Войти: `fetch('/api/auth/login', …)` из `javascript_tool`.

## Неочевидные вещи
- Тесты `retention` идут на общей базе пакета: проход стирает всё просроченное, поэтому тесты, которые считают удалённое, начинают с `clean(t)`.
- Журнал аудита в тестах не чистится; чистку проверяет `clean` через объявленную транзакцию и записи старше 91 дня.
- Демо-письма в очереди помечаются отправленными вместе со стиранием текста (`seed/applications.go`, `seed/offers.go`).
- `go.mod`: `toolchain go1.26.9` (на 2026-10-09 исправляет десять уязвимостей стандартной библиотеки). Если `make vulncheck` покраснел на новых находках в стандартной библиотеке, обновить строку `toolchain`, `README.md` и комментарий в `.github/workflows/ci.yml`.
- `TestUpDownUp` в `internal/migrate` перечисляет таблицы по миграциям: новая миграция с таблицей — новая строка и там.
- `npx prettier` в `web/` не запускать. Тесты сайта при нагрузке: `npx vitest run --maxWorkers=2`.
- Порт базы **5433** (D-028). Поддельные часы в тестах с `Truncate(time.Microsecond)`. Ошибки 500 только через `apierr.WriteInternal`. Тексты сайта только в `web/src/i18n/ru.ts`. Время по Москве.

## Известные проблемы и долги
- Политику конфиденциальности (`/privacy`) пишет юрист: черновик обновлён под факты (сроки, выгрузка), версия текста не менялась.
- Выгрузка собирается в браузере как Blob: человек с сотнями откликов даст сотни мегабайт (SCALING).
- `/api/landing` и каталоги без кеша, `OFFSET`-пагинация (срез 24). Файлы откликов в базе без проверки на вирусы (срез 23).
- Сквозные тесты не входят в CI (D-140, срез 28). Поведение tuna/localhost.run с X-Forwarded-For не проверено (T-31).
- `break-ui` и `impeccable audit/critique` по блоку «Ваши данные» не делались (просили ускориться).
- D-124: два почти одинаковых «Войдите…», кнопки «скоро» у входа через сервисы.
