Обновлено: 2026-10-14. Срез 15 «Анонимный режим и "скрыть от моей организации"» готов (`docs/slices/15-anonymous-mode.md`, D-199…D-202, метка `slice-15`). `ТЕКУЩИЙ: 16` (условия для учёного и выгрузка откликов), затем 17 и 30.

## Где остановились
- **Что появилось:** четвёртый режим профиля «Анонимно» и список «Скрыть от организаций» (до 30). Организации видят у анонима только научные данные (степень, звание, специальности, регион, h-index, счётчики публикаций и Q1–Q2, уровень R), без имени, должности, города, номеров, «о себе», навыков, записей и контактов. Имя открывается организации, которой человек откликнулся (не отозванный отклик) или ответил «Интересно» (D-199, D-202). Скрывшегося от организации её сотрудники не видят ни в каком режиме (D-200).
- **Что проверено:** `make test` зелёный (сервер 98,7%, `privacy` 100%, сайт 99,6% строк), браузер 1280 и 375 px, `differential-review`. `make e2e` 7 из 7.
- **Что ждёт пользователя вне кода:** хостинг и `docs/DEPLOY.md` (раздел 11); ручная модерация организаций (T-68, D-197, срез 30: пользователь сам опишет, до тех пор не проектировать); юрист: сроки хранения откликов (T-37), политика `/privacy` черновик (в неё добавлен абзац про анонимный режим).

## Неочевидные вещи
- **Как смотреть профиль в новом коде:** никогда не сравнивать `visibility` строкой. Собрать `privacy.Viewer` (владелец, `Staff`, `HiddenFrom`, `Revealed` через `ListUserOrgIDs` и `ProfileOrgRelations`), спросить `CanView`/`Detail`/`CanSeeContacts`. В списках организации имя решает `privacy.ShowsName(concealed, revealed)` (SQL отдаёт два флага). Безымянная карточка собирается только в `profiles.blindView` списком разрешённого: новое поле профиля по умолчанию в неё не попадает.
- Текст для поиска анонимного профиля собирает SQL-функция `refresh_profile_search` (миграция 00027): добавляя поле профиля в поиск, не класть его в ветку `anon`.
- Миграция 00027 помечена `scibox:contract` (ослабление проверки режима); откат версии безопасен: старый сервер читает `anon` как «скрыт».
- **iCloud Drive:** папка проекта в «Документах»; Mac выгружает файлы (флаг `dataless`), тесты сайта, `docker build` и `git` зависают. Зависимости сайта в `web/node_modules.nosync`. Лечится: `find web server deploy config -type f -flags +dataless -exec cat {} +`. Свободного места держать не меньше ~12 ГБ.
- **Помощники тестов** ставят `Binding: "test-registration-browser"` в `Meta` (`auth.env.meta()`, `testkit.Meta()`, `world.meta()` в `orgs`, `profiles`, `vacancies`); новый помощник с `auth.Meta{}` без этого получит `ConfirmedElsewhereError`.
- **Лимиты:** новый счётчик «не больше N» в транзакции начинать с `q.LockRateKey(ctx, kind+":"+key)` (I-80). Вне транзакции: `auth.reserve` или `profiles.spendKind`.
- **Текст человека:** строки из тела, пути и параметров проверяет периметр и `DecodeJSON` (`textsafe`); новые разборщики с фаззингом по образцу `*/fuzz_test.go`.
- Каждая сборка Docker даёт новый номер образа: имя образа базы содержит отпечаток (`deploy/db-image-tag`). Миграции после 00024 только добавляют (D-186).
- `go build`/`go test` без git-индекса: `GOFLAGS=-buildvcs=false`. Порт базы 5433. Ошибки 500 только через `apierr.WriteInternal`. Тексты сайта только в `web/src/i18n/ru.ts`. `npx prettier` в `web/` не запускать. Запуск dev-сервера через `preview_start` в этой среде падает («getcwd»): `make dev` из терминала.
- Mac: Docker (Colima) сейчас 5 ядер; вернуть: `colima stop && colima start --cpu 2 --memory 4`.
