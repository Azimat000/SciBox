# HANDOFF: записка следующей сессии

Обновлено: 2026-10-03, после среза 11.

## Где остановились
Срез 11 «Избранное, подписки, подбор, дедлайны» готов. Раздел `/favorites` из четырёх вкладок: «Избранное», «Подходящие» (`/matches`), «Поиски» (`/saved-searches`), «Сроки» (`/deadlines`). Закладка «В избранное» стоит в записях вакансий и на странице вакансии (только в режиме «Ищу работу»); «Сохранить поиск» в строке результатов поиска. Сервер раз в 5 минут сам рассылает сводки по сохранённым поискам (сразу / раз в день 9:00 МСК / раз в неделю) и напоминания о сроке (за 7 и за 1 день, не раньше 9:00 МСК). В настройках аккаунта два переключателя писем. Отчёт: `docs/slices/11-saved-matches.md`, решения D-104…D-113.

## Что дальше
Срез 12 «Лендинг» (`docs/ROADMAP.md`): `design-taste-frontend` + `impeccable`, для учёных и для организаций, строка поиска, свежие вакансии, реальные цифры из базы; поиск переезжает с `/` на `/vacancies` (сейчас `/` и `/vacancies` оба показывают поиск, D-069). Выдуманных цифр и логотипов нет (`PRODUCT.md`). Пока `/` = поиск, в шапке «Вакансии» ведёт на `/vacancies`.
- Что уже есть для лендинга: `GET /api/vacancies` (свежие вакансии), `GET /api/organizations` (число организаций в `total`), `GET /api/scientists` (число публичных профилей). Отдельного адреса «цифры лендинга» нет: если нужны числа, добавить один лёгкий публичный запрос.

## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. Остановка: Ctrl+C.
- `make db-reset`: пересоздать базу и демо-данные (30 организаций, 216 вакансий, 17 людей, 14 профилей, 14 откликов, 6 приглашений на вакансии, 18 избранных вакансий у шести учёных, 7 сохранённых поисков). Вход: `ksenia.lebedeva@demo.example.ru` (геология: 4 избранных, 2 поиска, подбор), `dmitry.korolev@demo.example.ru` (биология: избранное со сроком завтра и через 5 дней, 2 поиска), `alina.guseva@demo.example.ru`, `natalia.zhukova@…`, `artem.morozov@…`, `igor.tarasov@…`; организации: `olga.kuznetsova@…`; все `@demo.example.ru`, один пароль в `server/seed/seed.go`.
- `make test`: всё с проверкой покрытия (около 4 минут; сам поднимает Docker-контейнеры).
- Встроенный браузер Claude не запускает `make dev` из «Документов»: сервер и Vite запускать через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite --strictPort"`. Вход делать запросом `fetch('/api/auth/login', …)` через `javascript_tool`; режим «Нанимаю» включается `localStorage.setItem('scibox.role','employer')`, обратно `'seeker'` (после предыдущих сессий в браузере может остаться «Нанимаю»: тогда нет ни закладок, ни «Сохранить поиск»). Для телефона `resize_window` с пресетом `mobile`, потом вернуть `desktop`. Не запускать `npx vitest` из корня проекта: он не найдёт пакет (нужно из `web/`).
- Проверка фоновых писем руками: сдвинуть строки в базе (`UPDATE saved_searches SET checked_at = …, next_run_at = now()` и `UPDATE favorites SET created_at = …`) и подождать проход (до 5 минут); письма в Mailpit. Демо-вакансии «опубликованы» в прошлом, поэтому без сдвига границы сводок пустые.

## Известные проблемы и долги
- Не делали полный `/impeccable critique`, `/impeccable audit`, `break-ui` и `web-design-guidelines` для срезов 3, 4, 5, 7, 8, 9, 10, 11 и для поиска (только детектор, замеры и худший случай в браузере). Всё это входит в срез 13.
- Одинаковые сохранённые поиски не запрещены (только предел 20). Нет счётчика «новых по поиску» в списке поисков. Календарь сроков повесткой, без сетки месяца и без файла `.ics`; собеседования в нём нет.
- Подбор смотрит до 500 новейших вакансий нужных групп (D-109); у человека не может быть своих весов правил. Рассылки и напоминания работают в одном процессе сервера; два сервера сразу не дадут дублей (блокировки), но будут делить работу.
- Каталог ищет на лету без индекса (D-098). Русский стеммер не сводит «Седов» и «Седова». Нет поиска по организации учёного и по публикациям.
- Приглашение на вакансию: нет напоминаний, нет фильтра по вакансии на `/sent-offers`, отклик «по приглашению» ничем не помечен. Лимит 20 приглашений в сутки (D-099).
- Решение по отклику окончательное (D-088); истории смены статусов нет; нет поиска по имени кандидата и массовых действий. Время приглашений только московское (D-089).
- Отправленный отклик нельзя править. Письмо рекомендателя нельзя заменить. Нет напоминания рекомендателю.
- Письма об откликах, приглашениях и решениях отключить нельзя (D-106): отключаются только письма о новых вакансиях и о сроках.
- Публичные адреса `/api/recommendations/*` и публичный каталог `/api/scientists` не ограничены по IP. Файлы откликов лежат в базе (D-080), на вирусы не сканируются.
- Профиль: нет подсказки о заполненности, фото, импорта из ORCID (D-008). «Виден организациям» = любой сотрудник любой организации (D-072).
- Почта по SMTP без шифрования (только локально, D-020). Нельзя сменить почту, удалить аккаунт и организацию кнопкой (D-043, D-051).
- Запасной поиск вакансий «по похожим словам» без индекса (D-065). Заголовок вкладки всегда «SciBox».
- Текст `/privacy` черновик (нужна проверка юриста; версия текста та же, `2026-10-draft`). Тёмной темы нет. `mail` покрыт на 90,9%.
- Нет копирования вакансии и истории изменений; в списке на странице организации до 50 вакансий без листания.

## Неочевидные вещи
- Порт базы **5433** (D-028). Тесты с базой: общий помощник `internal/testkit`; в пакетах `applications`, `offers`, `matching` помощники в `helpers_test.go` (`newWorld`). В `matching` каждый тест начинает с того, что все старые вакансии уходят в архив, а старые поиски удаляются: фоновый проход берёт всё, что есть в базе. Часы теста свои (`world.clock`), а настоящее время идёт: у вакансий `published_at` настоящий, поэтому в тестах рассылки момент публикации при необходимости переставляют (`publishedAt`). Критичные зоны сервера = имена пакетов в `server/coverage.conf` (D-033).
- Фоновая работа: `matching.Service.Run` (раз в 5 минут) вызывает `SendDigests` и `SendReminders`; письма идут в `outbox`, отправитель берёт их раз в 2 секунды. Граница сводки `saved_searches.checked_at` двигается только вперёд; включение поиска после «не сообщать» сбрасывает её на «сейчас».
- Правила напоминаний целиком в SQL (`ListReminderCandidates`: ступень, окно, отклик, уже отправленное); в коде только перебор и запись. Время по Москве везде (D-057, D-089); в SQL `AT TIME ZONE 'Europe/Moscow'`.
- Уведомления: `notifications.Service.Emit(ctx, q, …)` в транзакции события; письма видов `saved_search` и `deadline_reminder` пропускаются, если человек их выключил (`mailCategory`). Контакты в уведомления организации не кладём.
- Права: приглашения и отклики спрашивают `access` через `orgs.ActorOf` и `orgs.ScopeOf(perm)` (D-102); приватность профиля решает `privacy.CatalogModes` и `CanView`. Подбор исключает вакансии организаций, где человек сам разбирает отклики (`access.ViewApplications`).
- Тесты фронтенда: `stubApi` (`web/src/test/api.ts`; `signedInAs` уже отвечает на настройки писем), фикстуры `web/src/test/matching.ts`, `offers.ts`, `applications.ts`; даты форматируются с « г.»; в режиме «Нанимаю» тест ставит `localStorage` ключ `scibox.role`. Закладка и «Сохранить поиск» есть в каждом списке вакансий: тесты, считающие кнопки и ссылки, должны искать по имени.
- Фронтенд: `VacancyCard` (`features/vacancies/VacancyList.tsx`) принимает `action` (заменить закладку или убрать), `footer`, `showDeadline`; `VacancyEntry` имеет слот `action` в правой колонке (на телефоне закладка уходит под текст через `display: contents`). Формы на `useForm` (мутация принимает поля аргументом); кнопки окна передаются в `Modal` через `actions`, а отправляет форму `form={id}`. `oxlint --deny-warnings` строгий: нельзя звать `new Date()` в отрисовке (срок в днях берём у сервера: `days_left`).
- Записи разделов профиля: одна таблица `profile_items` с JSON; новое поле записи = `profiles.ItemFields` + `validateItem` + `web/src/features/profile/sections.ts` + `ru.ts`.
- `vacancy_view`: добавили колонку в `vacancies` — пересоздайте представление в новой миграции и `go tool sqlc generate`. sqlc: nullable `text` → `*string`, `timestamptz` в `SET x = @now::timestamptz` писать с приведением; в запросах sqlc 1.30 путает `@today::date + 7` (передавайте границу параметром); для необязательного значения брать `LEFT JOIN`.
- Название продукта: `config/product.json` (D-029). Цвета и размеры только через токены; тексты только в `src/i18n/ru.ts`. Без эмодзи и юникод-значков вместо иконок (просьба пользователя): только нарисованные значки из `ui/icons.tsx`.
- Демо-данные детерминированы по структуре; сроки подачи считаются от дня загрузки; приглашения демо-откликов и статусы ставятся напрямую в базе, а приглашения на вакансии, избранное и поиски создают настоящие сервисы.
