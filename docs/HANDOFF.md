## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. Остановка: Ctrl+C.
- `make db-reset`: пересоздать базу и загрузить демо-данные (30 организаций, 216 вакансий, 9 людей). Вход: `elena.orlova@demo.example.ru` (владелец Сибирского института), `pavel.sokolov@…` (кадровик), `marina.zaitseva@…` (руководитель лаборатории и кадровик), `anton.vasilev@…` (без организации, ему пришло приглашение); все `@demo.example.ru`, один пароль в `server/seed/seed.go`.
- `make test`: всё с проверкой покрытия (сам поднимает Docker-контейнеры). Docker Desktop должен быть запущен.
- Встроенный браузер Claude не запускает `make dev` из «Документов»: запускать сервер и Vite через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite --strictPort"`. Поля форм удобно заполнять через `javascript_tool`. Скриншоты при эмуляции 1440 нестабильны (кадр уменьшен): размеры надёжнее мерить через `javascript_tool`.

## Известные проблемы и долги
- Письма уходят в фоне и не переживают падение сервера (нет очереди); для уведомлений в срезе 8 нужен «outbox».
- Почта по SMTP без шифрования (только локально, D-020); IP для ограничений из соединения.
- Нельзя сменить почту, удалить аккаунт и организацию кнопкой (D-043, D-051); отклонить приглашение нельзя.
- Запасной поиск «по похожим словам» просматривает все опубликованные вакансии без индекса (D-065): при росте базы добавить trigram-индекс.
- Поиск: нет подсказок при наборе слова, нет подсветки найденных слов, нет подсказки «какой фильтр обнулил выдачу», заголовок вкладки всегда «SciBox». Строка фактов вакансии из 6–8 равноправных пунктов (критика среза 6) не перестраивалась.
- Нет: `/impeccable critique` и `web-design-guidelines` по экранам срезов 3, 4 и 5; `web-design-guidelines` по поиску тоже не делался.
- Текст `/privacy` — черновик (про организации, вакансии, профили в нём ничего). Тёмной темы нет. `mail` покрыт на 90,9%.
- Справочники: коды регионов и номера документов для должностей сверены вторичными источниками (`docs/REFERENCE.md`).
- Нет копирования вакансии и истории изменений; в списке на странице организации до 50 вакансий без листания (остальные видны в поиске, где работает фильтр по организации только через адрес API, а не через сайт).

## Неочевидные вещи
- Порт базы **5433** (D-028). Тесты с базой: `testdb.New(t)` / `testdb.Create(t, migrated)`; пакеты `auth`, `orgs`, `vacancies` берут одну базу на весь пакет (`main_test.go`), тесты берут уникальные почты и названия, поэтому тесты поиска всегда сужают выдачу организацией (`OrgSlug`). Критичные зоны сервера = имена пакетов в `server/coverage.conf` (D-033).
- Права на вакансии: только `access.ManageVacancies` через `orgs.ActorOf`; в SQL ролей нет.
- `vacancy_view`: `v.*` раскрывается при создании; добавили колонку в `vacancies` — пересоздайте представление в новой миграции и `go tool sqlc generate`. Текст для поиска в представление НЕ входит (pgx не читает tsvector), он в `vacancy_search`.
- Триггеры `vacancy_search` пересобирают текст сами; сервис ничего для этого не делает. Новое поле вакансии, по которому нужно искать слова, добавлять в функцию `refresh_vacancy_search` (новая миграция) и в список колонок триггера.
- «Сегодня» в поиске = `Service.today()` (Москва); последний день срока включительно. `Service.now` подменяется в тестах часами.
- `stubApi` (`web/src/test/api.ts`): ключ маршрута, оканчивающийся на `*`, отвечает на любой адрес с таким началом (для поиска с произвольными параметрами).
- Фронтенд: адрес поиска разбирают `parseSearch`/`toParams` (`features/search/params.ts`): неизвестное молча отбрасывается; фильтры одного вида лежат в `multi` по именам параметров сервера.
- Формы: значения полей названы как поля сервера, поэтому ошибки сервера (`fields`) попадают в нужное поле сами. Данные, зависящие от того, кто смотрит, кэшируются под ключом с номером человека. Страницы для вошедших оборачиваются в `RequireUser`.
- Сервер ждёт JSON с `Content-Type: application/json` на всех запросах, меняющих данные, и своего `Origin`.
- Название продукта меняется в одном месте: `config/product.json` (D-029). Цвета и размеры только через токены; тексты только в `src/i18n/ru.ts`. `oxlint --deny-warnings` строгий.
- sqlc: nullable `text` → `*string`, `smallint` → `*int16`, `integer` → `*int32`, `date` → `time.Time`.
- Демо-данные детерминированы: `server/seed/generated.go` (22 организации, вакансии по профилям из `profiles.go`); сроки подачи считаются от дня загрузки.
