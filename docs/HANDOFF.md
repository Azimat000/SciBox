## Неочевидные вещи
- **Поток и сроки сервера**: без `SetWriteDeadline` на каждую запись `WriteTimeout` (60 с) рвёт поток; тест `TestStreamOutlivesServerTimeouts`. Caddy `write 5m`: сервер сам завершает поток через 4 минуты, сайт переподключается за секунду.
- **`pg_notify` несёт всю строку журнала** (около 300 байт), копия не читает базу ради отбора получателей; журнал нужен для досылки, добора после обрыва LISTEN и страховочного опроса (`id > последнего`).
- **Событие собирается для каждого получателя отдельно**: `is_me`, `client_id`, `editable_until`, имя учёного зависят от смотрящего (`framesFor`); новый вид события добавлять в `build` и в CHECK миграции.
- **`chat.state` и `unread.count` без номера**: не двигают `Last-Event-ID`; досыл снова собирает их из текущего состояния.
- **Переписки, перенесённые командой `chats backfill`, событий не объявляют** (`appendSystem(..., false)`).
- **Тесты писем и потока делят базу пакета**: `withMail` чистит `chat_unread_mail` в начале, иначе строки других тестов попадут в проход задачи.
- **Тесты cli, обходящие все адреса**, ставят `SCIBOX_CHAT_STREAM_MAX_AGE=100ms`, иначе запрос потока висит 4 минуты (таблица доступа, периметр).
- Прежние: состояние приглашения считается по строкам ленты (`events.ts`, D-223); на iCloud файлы проекта выгружаются (`dataless`), лечится `find web server deploy config -type f -flags +dataless -exec cat {} +`; зависимости сайта в `web/node_modules.nosync`; порт базы 5433; `make dev` из терминала; `npx prettier` в `web/` не запускать; тексты только в `web/src/i18n/ru.ts`.
