# HANDOFF: записка следующей сессии

Обновлено: 2026-10-03, после среза 7.

## Где остановились
Срез 7 «Профиль учёного» готов: `/profile` (мой профиль с правкой разделов, приватностью, PDF-резюме), `/profile/edit` (основное), `/scientists/:id` (страница для других с учётом приватности). Публикации добавляются вручную или по DOI через Crossref. В демо-данных 14 профилей. Отчёт: `docs/slices/07-profile.md`, решения D-071…D-078.

## Что дальше
Срез 8 «Отклик и рекомендательные письма» (`docs/ROADMAP.md`): отклик = профиль + сопроводительное + PDF-файлы + авто-CV; рекомендации по одноразовой ссылке без аккаунта; «Мои отклики»; центр уведомлений.
- Резюме уже есть: `profiles.Service.CV(ctx, user, nil)` отдаёт PDF своего профиля, `cv.Render` рисует по описанию документа. Для отклика нужен `profiles` метод, который отдаёт организации профиль и резюме без учёта режима приватности (человек сам откликнулся, D-072); сейчас такого метода нет специально: не обходить `privacy`, а завести явный путь «профиль для отклика».
- Файлы (PDF в отклик, письма) критичная зона `internal/files`: загрузка и выдача только тем, кому положено; папка `storage/uploads/` в git не попадает.
- Уведомления письмом: нужен «outbox» (письма уходят в фоне и не переживают падение сервера).
- Права на отклики: `access.ViewApplications` уже есть (руководитель видит только свои подразделения).

## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. Остановка: Ctrl+C.
- `make db-reset`: пересоздать базу и загрузить демо-данные (30 организаций, 216 вакансий, 17 людей, 14 профилей). Вход: `elena.orlova@demo.example.ru` (профиль публичный, большой), `igor.tarasov@…` (профессор, публичный), `marina.zaitseva@…` («организациям»), `pavel.sokolov@…` (кадровик), `roman.shiryaev@…` (скрытый), `dmitry.korolev@…` (открыт к предложениям); все `@demo.example.ru`, один пароль в `server/seed/seed.go`.
- `make test`: всё с проверкой покрытия (сам поднимает Docker-контейнеры). Docker Desktop должен быть запущен.
- Встроенный браузер Claude не запускает `make dev` из «Документов»: запускать сервер и Vite через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite --strictPort"`. Вход в браузере удобно делать запросом `fetch('/api/auth/login', …)` через `javascript_tool`, потом `navigate`. Скриншоты при эмуляции 1440 нестабильны: размеры надёжнее мерить через `javascript_tool`. PDF в картинку: `qlmanage -t -s 1000 -o . файл.pdf`.

## Известные проблемы и долги
- Не делали для среза 7: полный `/impeccable critique` и `web-design-guidelines` (только детектор и замеры в браузере). Не делали для срезов 3, 4, 5 и поиска из среза 6 тоже (`critique` по 3–5, `web-design-guidelines` по поиску).
- Профиль: нет подсказки о заполненности, нет фото, нет импорта из ORCID (D-008: позже), нет проверки, что ORCID принадлежит человеку.
- Резюме: PDF простой (одна колонка, без фото); заголовок раздела переносится с первой записью, но длинную запись может разорвать страница.
- «Виден организациям» = любой сотрудник любой организации (D-072); если понадобится только кадровикам или тем, на чьи вакансии человек откликался, это правка в `privacy` и `profiles.viewerOf`.
- Письма уходят в фоне и не переживают падение сервера (нет очереди); для уведомлений в срезе 8 нужен «outbox».
- Почта по SMTP без шифрования (только локально, D-020); IP для ограничений из соединения.
- Нельзя сменить почту, удалить аккаунт и организацию кнопкой (D-043, D-051); отклонить приглашение нельзя.
- Запасной поиск «по похожим словам» просматривает все опубликованные вакансии без индекса (D-065): при росте базы добавить trigram-индекс.
- Поиск: нет подсказок при наборе слова, нет подсветки найденных слов, нет подсказки «какой фильтр обнулил выдачу», заголовок вкладки всегда «SciBox».
- Текст `/privacy` — черновик (про организации, вакансии, профили в нём ничего: добавить срез про профили, там теперь хранятся сведения о публикациях, контактах). Тёмной темы нет. `mail` покрыт на 90,9%.
- Справочники: коды регионов и номера документов для должностей сверены вторичными источниками (`docs/REFERENCE.md`).
- Нет копирования вакансии и истории изменений; в списке на странице организации до 50 вакансий без листания.

## Неочевидные вещи
- Порт базы **5433** (D-028). Тесты с базой: `testdb.New(t)` / `testdb.Create(t, migrated)`; пакеты `auth`, `orgs`, `vacancies`, `profiles` берут одну базу на весь пакет (`main_test.go`), тесты берут уникальные почты и названия. Критичные зоны сервера = имена пакетов в `server/coverage.conf` (D-033).
- Приватность профиля: только через `privacy.Visibility.CanView/CanSeeContacts`; сервис собирает `privacy.Viewer` (`profiles.Service.viewerOf`). Ответ строится в `profiles.Service.build`: что смотрящему не положено (контакты, поле `visibility`), туда не попадает. Любой новый способ отдать профиль (каталог в срезе 10, отклик в срезе 8) идёт через ту же сборку или явный новый путь с тестом «кто × режим».
- Записи разделов профиля: одна таблица `profile_items` с JSON; новое поле записи = поле в `profiles.ItemFields` + проверка в `validateItem` + описание в `web/src/features/profile/sections.ts` + подписи в `ru.ts`. Имена полей в JSON общие для сервера и сайта.
- Crossref в тестах подставной (`fakeDOI` в сервисе, `httptest` в клиенте); в сеть тесты не ходят. Демо-публикации с DOI `10.5555/demo.*`.
- Шрифты резюме лежат в `server/internal/cv/fonts` (статические, подмножество символов); если нужны другие символы, пересобрать подмножество (см. `docs/REFERENCE.md`).
- Права на вакансии: только `access.ManageVacancies` через `orgs.ActorOf`; в SQL ролей нет.
- `vacancy_view`: `v.*` раскрывается при создании; добавили колонку в `vacancies` — пересоздайте представление в новой миграции и `go tool sqlc generate`. Текст для поиска в представление НЕ входит, он в `vacancy_search`; триггеры пересобирают его сами.
- «Сегодня» в поиске = `Service.today()` (Москва); последний день срока включительно. Часы подменяются в тестах (`Service.now`); тесты не должны сравнивать подставное время с настоящим (так упал `TestHTTPFullCycle`, D-078).
- `stubApi` (`web/src/test/api.ts`): ключ маршрута, оканчивающийся на `*`, отвечает на любой адрес с таким началом.
- Фронтенд: формы строятся на `useForm` (значения названы как поля сервера, поэтому ошибки `fields` попадают в нужное поле сами); данные, зависящие от того, кто смотрит, кэшируются под ключом с номером человека; страницы для вошедших оборачиваются в `RequireUser`.
- Сервер ждёт JSON с `Content-Type: application/json` на всех запросах, меняющих данные, и своего `Origin`.
- Название продукта меняется в одном месте: `config/product.json` (D-029). Цвета и размеры только через токены; тексты только в `src/i18n/ru.ts`. `oxlint --deny-warnings` строгий.
- sqlc: nullable `text` → `*string`, `smallint` → `*int16`, `integer` → `*int32`, `date` → `time.Time`.
- Демо-данные детерминированы; сроки подачи вакансий считаются от дня загрузки; профили загружаются через сервис профилей (после основной транзакции).
