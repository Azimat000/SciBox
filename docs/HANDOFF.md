# HANDOFF: записка следующей сессии

Обновлено: 2026-10-10. Срез 24 «База данных под объём "вся наука РФ"» готов (`docs/slices/24-database-at-scale.md`, D-161…D-166). Идёт серверная очередь 18–29 (D-138), потом продуктовые 15–17. `ТЕКУЩИЙ: 25` (несколько копий сервера и фоновые задачи).

## Где остановились
- **Поиск и каталог.** Тексты поиска лежат в `vacancy_search` и `profile_search`, собирают их триггеры; поиск отдаёт не больше первой тысячи результатов (`capped`, D-161); запросы устроены цепочкой `hits → found → page → карточки` (`db/queries/vacancies.sql`, `profiles.sql`). Порог поиска с опечатками 0,5 задан на базу миграцией 00021 (D-163).
- **Пул и сроки.** `internal/dbpool`: `statement_timeout` 10 с, `idle_in_transaction_session_timeout` 30 с, `plan_cache_mode = force_custom_plan`, `random_page_cost = 1,1`, журнал медленных запросов. Пул с этими настройками только у `serve`; `migrate`, `seed`, `journals` открывают обычные соединения (долгие операции). Ответ 503 `database_busy`.
- **Кеш.** `internal/httpcache`: `/api/landing` 30 с, `/api/reference` 10 мин; у них `ETag` и `Cache-Control: public`.
- **Замеры.** На половине объёма: 36 запросов из 42 укладываются в 50 мс по p95, остальные не больше 100 мс (`docs/SCALING.md`).

## Что дальше
`ТЕКУЩИЙ: 25`: команда `worker` для фоновых задач, безопасность при нескольких копиях (T-23), повторы с паузой, таймауты Crossref и SMTP (T-24). Скиллы среза в ROADMAP. Что стоит помнить: пул `dbpool` один на процесс; в срезе 25 у `worker` и `serve` суммарно не больше 60 из 100 соединений базы.

## Как запустить
- `make dev`: база, почта, хранилище файлов (8333), ClamAV (3310), миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). `make db-reset`: всё заново с демо-данными. Вход: `elena.orlova@demo.example.ru` (владелец), `dmitry.korolev@demo.example.ru` (соискатель); пароль в `server/seed/seed.go`.
- `make test`: около 10 минут (линтер, vulncheck, сервер с порогами, сайт). `make load-data` (40 минут, масштаб 0,5, ≈ 7 ГБ на диске) и `make load-check` (минута) нужны только для замеров среза 24 и 27; **на этом Mac места мало, база `scibox_load` удалена в конце среза 24** (пересоздаётся командой `make load-data`; перед ней освободить ≥ 10 ГБ и поднять память базы: `SCIBOX_PG_SHARED_BUFFERS=768MB docker compose up -d postgres`; при 768 МБ ClamAV не помещается в память Docker, перед `make test` вернуть умолчание 256 МБ).
- Встроенный браузер Claude не запускает `make dev` из «Документов»: сервер и Vite через Bash в фоне (`cd server && go build -o bin/scibox ./cmd/api && ./bin/scibox migrate up && ./bin/scibox serve`, `cd web && npm run dev -- --strictPort`), затем `preview_start` с `url`.

## Неочевидные вещи
- **Папка проекта лежит в iCloud («Документы») и при нехватке диска macOS выгружает файлы в облако.** В срезе 24 это случилось: `.git/index` и 1700 файлов `node_modules` стали «dataless» и не читались («Operation timed out»). Помогло: `GIT_INDEX_FILE=<другой файл> git …` (временный индекс) и чтение файлов (`cat`) для скачивания. Проверка: `ls -lO файл | grep dataless`. Исправить `.git/index` навсегда: убедиться, что файл скачался (`cat .git/index | wc -c`), иначе `rm .git/index && git reset`. Держать ≥ 10 ГБ свободного места (докер здесь — Colima: после удаления баз вернуть место Mac командой `colima ssh -- sudo fstrim -av`, иначе удалённое остаётся занятым на диске Mac); подумать о выводе проекта из синхронизации.
- `go build` и `go test` без git-индекса требуют `GOFLAGS=-buildvcs=false`.
- Любое изменение запроса поиска проверять на `scibox_load` (`EXPLAIN`): универсальные запросы чувствительны к плану. `ORDER BY` с `NULLS LAST` требует индекса с `NULLS LAST` (`profiles_h_idx`).
- `Config.MaxResults` у `vacancies` и `profiles` нужен только тестам (малый предел).
- Тесты хранилища и антивируса падают, а не пропускаются, если контейнеры не подняты. ClamAV грузит базы 1–3 минуты и держит ~1,5 ГБ памяти Docker; если `unhealthy` дольше пяти минут, смотреть память (`docker stats`) и пересоздать (`docker compose up -d --force-recreate clamav`).
- Порт базы **5433**. Ошибки 500 только через `apierr.WriteInternal`. Тексты сайта только в `web/src/i18n/ru.ts`. Время по Москве. `npx prettier` в `web/` не запускать.

- T-45 (поиск по частому слову под нагрузкой), T-46 (параметры соединения за PgBouncer), T-47 (`ALTER DATABASE` на хостинге), T-41, T-43, T-44: `docs/SECURITY.md`.

- D-124: два почти одинаковых «Войдите…», кнопки «скоро» у входа через сервисы. Политика `/privacy` черновик.
