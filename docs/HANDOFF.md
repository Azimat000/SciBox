# HANDOFF: записка следующей сессии

Обновлено: 2026-10-02, после среза 3.

## Где остановились
Срез 3 «Аккаунты» готов: регистрация (с согласием на ПДн), письмо с подтверждением, вход и выход, сброс пароля, настройки (имя, пароль, «выйти на других устройствах»), кнопки «скоро» для ORCID / Яндекс / ВК / Госуслуг, черновик политики `/privacy`. Отчёт: `docs/slices/03-accounts.md`, решения D-039…D-044.

## Что дальше
Срез 4 «Организации и подразделения» (`docs/ROADMAP.md`).
- Вошедший человек на сервере: `auth.FromContext(r.Context())` (после `d.Auth.SameOrigin` и `Authenticate`, они уже стоят на всём `/api`). Закрытые адреса оборачивать в `auth.Handler.RequireUser`. Новые адреса подключать в `httpapi.NewRouter` рядом с `d.Auth.Mount`.
- Роли в организации (владелец, кадровик, руководитель подразделения) класть в `server/internal/access` (критичная зона 97%), не в `auth`.
- Человек на сайте: `useMe()` из `features/auth/api.ts` (`user`: `undefined` пока грузится, `null` если не вошёл). После входа или выхода всегда `await setMe(client, user)`: он сначала отменяет запоздавший ответ «кто я?».
- Формы: `useForm` (`features/auth/useForm.ts`) даёт значения, ошибки (клиентские и от сервера по полям), фокус на первое неверное поле после отправки. Ошибки полей сервер отдаёт как `fields` в ответе 422.
- Подставной сервер в тестах: `stubApi` из `src/test/api.ts` (по умолчанию «никто не вошёл», лишний запрос даёт 404).

## Как запустить
- `make dev`: база + Mailpit, миграции, сервер (127.0.0.1:8080) и сайт (http://localhost:5173). Письма: http://localhost:8025. Остановка: Ctrl+C.
- `make test`: всё с проверкой покрытия (сам поднимает Docker-контейнеры). `make db-reset`, `make migrate`, `make seed` (пока заглушка), `make sqlc`.
- Docker Desktop должен быть запущен (`open -a Docker`).
- Встроенный браузер Claude не запускает `make dev` из «Документов»: запускать через Bash в фоне, затем `preview_start` с `url`. Остановка: `pkill -f "bin/scibox serve"; pkill -f "vite --strictPort"`.
- Снимки страниц: скрипт на `playwright-core` (лежит в `~/.npm/_npx/*/node_modules/playwright-core`) + `~/Library/Caches/ms-playwright/chromium_headless_shell-1234/`. Снимки среза 3: `.impeccable/review/slice3/`.

## Известные проблемы и долги
- Письма уходят в фоне и не переживают падение сервера (нет очереди в базе). Для писем-уведомлений в срезе 8 нужна очередь («outbox»).
- Почта по SMTP без шифрования и без пароля (только локально, D-020). Перед публикацией в интернет добавить STARTTLS и вход.
- IP для ограничений берётся из соединения. За прокси (когда будет публикация) нужен доверенный заголовок.
- Нельзя сменить почту, удалить аккаунт и отозвать согласие кнопкой: в `/privacy` написано «по обращению». Сделать в срезе 7, когда появятся данные профиля.
- Текст `/privacy` — черновик без указания оператора; нужна проверка юристом.
- Не запускались полностью `/impeccable audit`, `critique`, `break-ui`, `web-design-guidelines` по новым экранам (сделан один круг снимков 1440 и 375 и ручные проверки). Сделать в срезе 6 вместе с поиском.
- Тёмной темы нет. `mail` покрыт на 90,9%: не покрыты ошибки установки таймаута соединения и кодирования тела.
- Шапка схлопывается в меню при ширине меньше 66rem (было 52rem): иначе имя пользователя и кнопки не помещаются (DESIGN.md обновлён).

## Неочевидные вещи
- Порт базы **5433** (D-028). Тесты с базой: `testdb.New(t)` / `testdb.Create(t, migrated)`; пакет `auth` берёт одну базу на весь пакет (`main_test.go`), тесты берут уникальные почты и IP. Критичные зоны сервера = имена пакетов в `server/coverage.conf` (D-033).
- `auth.Service` принимает интерфейс `DB`, а не пул: тест `fault_test.go` оборачивает его и ломает n-й запрос. При добавлении операций добавлять их в таблицу `TestDatabaseFailuresAreNeverSwallowed`.
- Запрос `confirm-email` на сайте идёт через `useQuery` с общим ключом: иначе режим StrictMode послал бы его дважды и сжёг ссылку.
- Выход чистит память страницы, но оставляет запрос «кто я?» (`removeQueries` с исключением): через `client.clear()` шапка теряла связь с запросом.
- Название продукта меняется в одном месте: `config/product.json` (D-029).
- React Router 8: `RouterProvider` из `react-router/dom`. `oxlint --deny-warnings` строгий: `react/only-export-components`, `react/purity`, `react/refs` (ref нельзя читать при отрисовке), `set-state-in-effect`.
- Все цвета и размеры только через токены `src/styles/tokens.css`; жёлтый маркер единственный акцент. Тексты только в `src/i18n/ru.ts`.
- Сервер ждёт JSON с `Content-Type: application/json` на всех запросах, меняющих данные, и закрывает чужой Origin. Через прокси Vite это работает.
