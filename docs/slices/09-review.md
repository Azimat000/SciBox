# Срез 9. Разбор откликов организацией

Статус: готов. 2026-10-03.

## Цель
Организация видит все отклики на свои вакансии списком, открывает карточку кандидата и ведёт отклик по статусам:
отправлен → просмотрен → приглашение → принят / отказ. Приглашение бывает трёх видов (собеседование, контакты организации,
просьба оставить контакты). Соискатель отвечает на приглашения на странице своего отклика. Обе стороны получают уведомления
на сайте и письмом.

## Задачи

### Сервер
- Миграция `00009`: таблица `application_invitations`, поля `applications.decision_note` и `decided_by`.
- Таблицы допустимых переходов: статусы отклика (для организации) и статусы приглашения (`internal/applications/transitions.go`).
- Список откликов организации: `GET /api/my/candidates` (по правам `access.ViewApplications`, фильтры вакансия и статус, счётчики) и
  `GET /api/my/candidate-vacancies` (по каким вакансиям есть отклики; для фильтра и для счётчиков в «Моих вакансиях»).
- Автоматическое «просмотрен» при открытии карточки организацией.
- Решение: `POST /api/applications/{id}/status` (принят / отказ, с короткой запиской соискателю).
- Приглашения: создать, отменить, ответить (подтвердить / предложить время / оставить контакты), принять предложенное время.
- Уведомления и письма обеим сторонам на каждое событие.

### Интерфейс
- `/candidates`: список откликов (вкладки по статусам, фильтр по вакансии, страницы).
- `/candidates/:id`: панель решения (пригласить, принять, отказать), приглашения с состояниями.
- `/applications/:id`: приглашения для соискателя с формами ответа, записка организации к решению.
- «Мои вакансии»: число откликов (и новых) со ссылкой на список.
- Меню «Отклики» перестаёт быть заглушкой.

### Данные
- Демо-приглашения во всех видах и состояниях, записки к решениям.

## Что проверяем
Таблицы «кто → что → можно / нельзя» для каждой операции (владелец, кадровик, руководитель своего и чужого подразделения,
посторонний, соискатель); таблицы переходов; гонки (двое открывают карточку, двое отвечают на приглашение); уведомления и
письма каждой стороне; отказ не оставляет следов; браузер (desktop и mobile), письма в Mailpit.

## Риски
- Критичная зона (отклики и статусы): порог 97%.
- Время приглашений: решаем одно правило (московское время), чтобы не путаться с часовыми поясами.

## Сделано

**Сервер**
- Миграция `00009`: таблица `application_invitations`, поля `applications.decision_note` и `decided_by`.
- `applications/transitions.go`: одна таблица переходов статусов для организации и таблицы состояний приглашений (D-088, D-090).
- `applications/review.go`: «просмотрен» при первом открытии карточки (один раз, с уведомлением соискателю); решение (принят / отказ, с запиской); приглашения трёх видов (собеседование, контакты, просьба о контактах); ответы соискателя (подтвердить, предложить время, оставить контакты) один раз; принять предложенное время; отменить приглашение; список откликов организации по правам `ViewApplications` с отбором по вакансии и статусу, счётчики; вакансии с откликами.
- `invitation_input.go` (проверки), `notices.go` (тексты уведомлений и писем).
- Отзыв отклика закрывает открытые приглашения. Уведомления и письма обеим сторонам на каждое событие (D-092).
- HTTP: `GET /api/my/candidates`, `GET /api/my/candidate-vacancies`, `POST …/status`, `POST/DELETE …/invitations`, `…/answer`, `…/accept-proposal`.
- Демо-данные: приглашения всех видов и состояний, записки к решениям (D-094).

**Интерфейс**
- `/candidates`: список откликов (вкладки со счётчиками, отбор по вакансии, страницы, состояния «пусто», «ошибка», «длинные данные»).
- `/candidates/:id`: панель решения («Пригласить», «Принять», «Отказать»), приглашения с действиями, окна `InviteModal` и `DecisionModal`.
- `/applications/:id`: приглашения для соискателя с ответами (`AnswerModals`), решение и записка организации. «Мои отклики»: отметка «Ждёт вашего ответа».
- «Мои вакансии»: «N откликов, новых M» со ссылкой. Меню «Отклики» больше не заглушка. Колокольчик показывает многострочные уведомления.

## Отступления от плана
- Не делали отдельной вкладки «Новые» с автоматическим прокручиванием и поиска по имени кандидата: отбор только по вакансии и статусу.
- Пересмотр решения не предусмотрен (D-088), история смены статусов не хранится (хранится только последнее решение и кто его принял).
- Семь вкладок статусов на телефоне занимают три строки (читается и нажимается, но можно компактнее).
- Полный `/impeccable audit`, `critique`, `break-ui` и `web-design-guidelines` не запускали (как и в срезах 3–8): только детектор хука при правках и проверка в браузере; худшие данные проверены тестами (длинное имя, длинная ссылка, чужая схема, пустые поля).

## Проверки
- `make test` зелёный (сервер и сайт, пороги соблюдены). Починен тест миграций `TestUpDownUp` (новая таблица).
- Браузер: компьютер и телефон 375 px, вход как Ольга Кузнецова (владелец) и Дмитрий Королёв (соискатель): список откликов, карточка, «принять предложенное время» работает, новое приглашение создано через форму, письма пришли в Mailpit (`Приглашение на собеседование`, `Время собеседования согласовано`). Горизонтального переполнения на телефоне нет.
