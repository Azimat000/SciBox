# Срез 33: навыки из справочника с подсказками

Статус: готов (2026-10-14, метка `slice-33`). Решения: D-136 (два списка навыков), D-211 (источник), D-212 (свои навыки), D-186 (миграции только добавляют). Скиллы: golang-database, golang-security, golang-testing, sharp-edges; интерфейс: impeccable, break-ui.

## Цель
Научные и общие навыки в профиле выбираются поиском: человек печатает, под полем подсказки из справочника, выбранные навыки стоят чипами. Нет нужного: в конце списка «Не нашли? Добавить «…»». Профиль по-прежнему хранит строки (`research_skills`, `general_skills`).

## Решения пользователя (2026-10-14)
- Источник: свой справочник, составленный командой (готового русского с открытой лицензией нет: ESCO и O*NET без русского, hh.ru запрещает копировать). Исследование `web-researcher` записано в `docs/REFERENCE.md`.
- Свои навыки человека остаются только в его профиле, в чужих подсказках не показываются (до модерации, срез 30).

## Задачи
Сервер
- миграция 00030: таблицы `skills` (навык: вид, группа, каноническое написание, ключ) и `skill_terms` (название и синонимы: ключ, слова, `tsvector`), индексы;
- пакет `internal/skills`: ключ сравнения (`Key`: регистр, «ё», тире, пробелы), разбор CSV, загрузка заменой целиком (как журналы), поиск (точное, начало, начало слова, словоформы, опечатки), HTTP `GET /api/skills`;
- файл справочника `internal/skills/data/skills.csv`, встроен в сервер; команда `scibox skills load`, строка в `reference_sources`;
- `profiles`: приведение навыков к каноническому написанию при сохранении, повторы без учёта регистра и «ё»;
- периметр: политика частоты, строка таблицы прав доступа.

Интерфейс
- `SkillsInput` получает подсказки (комбобокс WAI-ARIA, клавиатура, телефон), «Не нашли? Добавить «…»», состояния: загрузка, ошибка, пусто, полный список;
- тексты в `ru.ts`.

Данные: навыки у демо-людей.

## Проверяем
- каждый ярус поиска отдельной строкой таблицы; опечатки; ё; регистр; пределы; без входа 401;
- сохранение профиля: канонизация, синонимы сводятся, повторы убираются, неизвестное остаётся как есть, прежние навыки не пропадают;
- замена справочника не ломает профили (они хранят строки);
- качество встроенного файла (повторов нет, длины, группы).

## Риски
- Справочник составлен вручную: может быть неполным; «Не нашли? Добавить» закрывает это, расширение идёт правкой одного CSV.
- Канонизация при сохранении меняет написание, которое человек ввёл: показываем это сразу после сохранения, а в подсказке синоним помечен.

## Готово, когда
- [x] оба поля навыков работают через подсказки на компьютере и телефоне;
- [x] есть «Не нашли? Добавить»;
- [x] существующие навыки в профилях не потеряны и не продублированы;
- [x] источник справочника и лицензия записаны (`reference_sources`, `docs/REFERENCE.md`);
- [x] тесты и `make test` зелёные.

## Сделано
Сервер
- Миграция `00030_skills.sql`: `skills`, `skill_terms` (ключ, слова, основы слов, четыре индекса), только добавление.
- Пакет `internal/skills`: `Key`, разбор файла с номерами строк в ошибках, загрузка заменой целиком, поиск в четыре яруса и по похожим написаниям, `Canonical`, `GET /api/skills`.
- Справочник `skills.csv`: 919 навыков (научных 5 хх, общих 3 хх: см. команду `skills load`), группы: методы, приборы, программы, области, языки, офис, компьютер, дизайн, работа с людьми, преподавание, управление, личные качества, документы и допуски.
- `skills load` в `make migrate`, `make db-reset`, `release`, `scripts/e2e-db`, `scripts/load-data`.
- `profiles`: приведение к каноническому написанию при сохранении, ключ повторов без учёта «ё» и тире.
- Периметр: политика `skill_suggest` (240 в минуту с аккаунта), строка в таблице прав доступа.
- Демо-данные: оба списка навыков у всех 14 демо-учёных (часть записана синонимами, часть своими).

Интерфейс
- `SkillsInput` с подсказками (комбобокс WAI-ARIA), «Не нашли? Добавить «…»» закреплена внизу списка, список на всю ширину строки «поле + кнопка»; Enter, запятая, вставка списка и потеря фокуса работают как раньше; состояния: поиск, нет в справочнике, похожие написания, недоступный справочник, список полон.

## Отступления от плана
- Справочник составлен нами, а не взят из внешнего источника: ни у ESCO, ни у O*NET нет русского, hh.ru запрещает копировать; решение пользователя (D-211).
- Старые строки в профилях не переписываются массово при загрузке справочника, а приводятся при следующем сохранении профиля: без потерь и повторов, не трогает 350 тысяч строк (D-213).
- Поиск по раскладке («руегщт» вместо «python») не делался: отдельная доработка при необходимости.

## Проверки
- `make test` зелёный (2026-10-14): линтер 0 замечаний, vulncheck без находок, сервер, сайт 61 файл 1026 тестов.
- `make lint-new` 0 замечаний после последних правок; `go test ./internal/skills ./internal/profiles ./internal/migrate`, `./internal/cli` (`TestRelease`, `TestSkillsLoad`, `TestSeedLoads`, `TestAccessTable`, `TestPerimeter`) зелёные после расширения справочника.
- `FuzzKey` 20 секунд, 290 тысяч запусков без замечаний.

## Обзор правок в критичной зоне (differential-review, свой)
- `profiles.validate.skills`: ключ повторов теперь `skills.Key`; сужения нет, повторы отбрасываются так же или шире (регистр, «ё», тире); тесты `TestValidateSkills`.
- `profiles.Service.check`: два запроса к `skill_terms` внутри той же транзакции, что и сохранение; отказ базы доходит до вызывающего (`TestDatabaseFailuresAreNeverSwallowed`); пустой список запросов не делает.
- Утечки: справочник не содержит данных людей; подсказки только вошедшим; запрос к базе только параметрами.
- Находок, требующих исправления, нет. Остаточный риск: канонизация меняет написание, введённое человеком; он видит итог сразу после сохранения (список на странице профиля).
