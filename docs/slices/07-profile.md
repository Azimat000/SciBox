# Срез 7: профиль учёного

Статус: готов. 2026-10-03.

## Цель
Учёный заполняет научный профиль вместо резюме: степень и звание, специальности ВАК, идентификаторы (ORCID, SPIN, Scopus, WoS) и h-index, публикации (вручную или по DOI), гранты, патенты, преподавание, опыт, образование. Сам выбирает, кто его видит: никто / организации / все. У профиля есть публичная страница и автоматический PDF с CV. Профиль станет основой для отклика (срез 8) и каталога учёных (срез 10).

## Решения (дописываются в DECISIONS, D-071…)
- Приватность решает отдельный пакет `internal/privacy` (чистая логика, критичная зона): кто (владелец, сотрудник организации, вошедший, аноним) × режим (скрыт, организациям, публичный) → видит профиль / видит контакты. Чужим скрытый профиль «не существует» (404).
- Разделы профиля (образование, опыт, публикации, гранты, патенты, преподавание) хранятся одной таблицей записей с JSON-полями; поля и пределы проверяет код по виду записи. Основные поля (степень, идентификаторы, h-index, о себе) лежат колонками.
- Публикация по DOI: сервер спрашивает Crossref (без ключа), отдаёт найденное в форму, человек проверяет и сохраняет. Если Crossref недоступен, форма остаётся ручной.
- CV: PDF собирает сервер (шрифты Golos Text и Literata лежат в проекте), по тем же правилам приватности.

## Задачи

### Сервер
1. Миграция `00007_profiles.sql`: `profiles`, `profile_specialties`, `profile_items`.
2. `internal/privacy`: режимы и таблица «кто видит что».
3. `internal/crossref`: клиент (таймаут, ограничение размера, разбор), нормализация DOI.
4. `internal/profiles`: сервис (получить/создать свой профиль, сохранить основное, приватность, записи разделов, поиск по DOI, чужой профиль с учётом приватности), проверки полей, HTTP, сборка CV.
5. `internal/cv`: общий отрисовщик PDF (fpdf, встроенные шрифты с кириллицей).
6. Демо-данные: учёные с профилями во всех режимах приватности.
7. Тесты: приватность таблицей, права «владелец / сотрудник / вошедший / аноним × режим», проверка каждого поля, DOI (подставной Crossref), сбои базы, PDF.

### Интерфейс
1. `/profile`: мой профиль как страница журнала с кнопками правки у каждого раздела; блок приватности; кнопка «Скачать CV».
2. `/profile/edit`: форма основного (степень, звание, специальности, идентификаторы, h-index, контакты).
3. Окна добавления и правки записей по видам; в публикациях «Найти по DOI».
4. `/scientists/:id`: страница профиля для других (с учётом приватности); «скрыт» = «такого профиля нет».
5. Пункт «Профиль» в меню человека; состояния: пусто, загрузка, ошибка, длинные данные.

## Что проверяем
Заполнить профиль; добавить публикацию по DOI (и когда Crossref молчит); сменить приватность и открыть страницу из другого аккаунта, из аккаунта организации и без входа; скачать CV; демо-учёные на странице; телефон 375 и компьютер 1440.

## Риски
- Утечка контактов или скрытого профиля: поэтому отдельный критичный пакет и таблица на каждую пару «кто × режим».
- Кириллица в PDF: шрифты со статическими начертаниями, проверка на длинных и необычных данных.
- Crossref отвечает по-разному (нет автора, нет года, DOI с «<»): разбор терпимый, ручной ввод всегда доступен.
- Большой объём интерфейса: формы по описанию полей (один компонент на все виды записей).

## Сделано

Сервер
- Миграция `00007_profiles.sql`: `profiles`, `profile_specialties`, `profile_items`; запросы sqlc `profiles.sql`.
- `internal/privacy`: режимы и таблица «кто видит профиль и контакты».
- `internal/crossref`: клиент Crossref, нормализация DOI, терпимый разбор ответа.
- `internal/profiles`: сервис (свой профиль, чужой с учётом приватности, основные поля, приватность, 6 видов записей, поиск по DOI с лимитом, резюме), проверки полей (ORCID с контрольной суммой, форматы SPIN, Scopus, WoS, годы, длины), HTTP (`/api/profile*`, `/api/scientists/{id}`), сборка резюме.
- `internal/cv`: PDF по описанию документа; шрифты Golos Text и Literata (кириллица) лежат в проекте.
- Настройки `SCIBOX_CROSSREF_URL`, `SCIBOX_CROSSREF_MAILTO`.
- Демо-данные: 8 новых людей, 14 заполненных профилей (7 публичных, 4 «организациям», 3 скрытых).

Интерфейс (`web/src/features/profile`)
- «Мой профиль» `/profile`: профиль как страница журнала, у разделов «Добавить / Изменить / Удалить», блок «Кто видит профиль» (сохраняется сразу), кнопки «Изменить основное», «Скачать резюме», «Как видят другие».
- Окно записи одно на все 6 видов (поля описаны в `sections.ts`); в публикациях «Найти по DOI» подставляет поля из Crossref.
- Форма основного `/profile/edit`: степень и звание (подробности только при степени), специальности (до 5), идентификаторы, h-index, контактная почта.
- Страница учёного `/scientists/:id`; пункт «Мой профиль» в меню человека.

## Отступления от плана
- Импорт публикации по DOI не сохраняет запись сам, а заполняет форму: человек проверяет данные (Crossref иногда ошибается в авторах и названиях).
- Отдельной страницы «приватность» нет: блок стоит наверху «Моего профиля».
- Чужое резюме скачивают только вошедшие (чтобы публичные профили нельзя было собирать пачкой без входа).
- Не делали: подсказки о заполненности профиля, импорт из ORCID (решение D-008: позже), загрузка фото.
- По дороге починен хрупкий тест аккаунтов (D-078): он держался на дате и упал на вторых сутках.
