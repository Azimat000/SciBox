# Срез 20. Аккаунты и сессии: усиление

Начат 2026-10-08. Серверная очередь (D-138). Угрозы T-10…T-14 из `docs/SECURITY.md`. Решения пользователя: D-142.

## Цель

Человек видит, где он вошёл, и может завершить любую сессию; меняет почту и удаляет аккаунт сам, без обращения; опасные действия требуют свежего пароля; о входе с нового устройства и смене пароля приходит письмо; пароли из утёкших списков не принимаются.

## Что уже было до среза (проверено по коду)

- Смена пароля в настройках завершает другие сессии, сброс по ссылке завершает все (`ChangePassword`, `ResetPassword`), письмо «пароль изменён» уходит в обоих случаях.
- Кнопка «Выйти на других устройствах» (`POST /api/account/sessions/revoke-others`).
- При входе всегда создаётся новая сессия. Не хватает: старая сессия из cookie браузера при входе не удаляется.
- Список частых паролей — 31 штука в коде.

## Задачи

### Сервер
1. Миграция `00016_account_security.sql`: `sessions.reauth_at`; `auth_tokens.new_email` и назначения `change_email`, `revert_email`; таблица `known_devices`; `users.deletion_due_at`, `users.deleted_at`, `profiles.visibility_before_deletion`; `applications.anonymized_at` (письмо и почта могут быть пустыми только у обезличенного).
2. `auth`:
   - список сессий (`GET /api/account/sessions`: устройство по User-Agent, когда вошли, когда были), завершение одной (`DELETE /api/account/sessions/{id}`); вход удаляет сессию из старой cookie (T-10);
   - «свежий пароль» (`POST /api/account/reauth`, 10 минут на сессию): нужен для смены почты, удаления аккаунта, назначения владельца организации (T-12);
   - смена почты: ссылка на новый адрес, по ней почта меняется, на старый адрес уходит письмо со ссылкой «это не я» (вернуть почту и завершить все сессии) (T-11);
   - удаление аккаунта: просьба → 14 дней на отмену (профиль сразу скрыт, все сессии завершены, письмо с датой) → фоновая задача стирает данные (T-11);
   - письмо «вход с нового устройства» по cookie устройства (T-13);
   - список частых паролей: 8 923 пароля длиной от 10 знаков из списка NCSC 100k (SecLists, MIT) + свои русские; проверка и в русской раскладке (T-14);
   - тест: ответы регистрации, повтора письма и сброса одинаковы для существующей и несуществующей почты.
3. Новый пакет `internal/erasure` (критичная зона): что стирается и обезличивается при удалении аккаунта, проверка организаций, где человек единственный владелец.
4. `orgs`: назначение владельцем (смена роли и приглашение) требует свежего пароля.
5. `applications`: обезличенный отклик отдаётся организации с пометкой `anonymized`, без письма, профиля, файлов.

### Интерфейс
- Настройки разделены на две вкладки: «Аккаунт» (`/account`: имя, письма) и «Безопасность» (`/account/security`: пароль, сессии, почта, удаление).
- Окно «Введите пароль» само появляется, когда сервер просит свежий пароль, и повторяет действие.
- Страница подтверждения новой почты и страница «это не я» (`/confirm-email-change`, `/revert-email-change`).
- Полоса «Аккаунт будет удалён …, отменить» у вошедшего во время срока отмены.
- Карточка и список откликов у организации: «Аккаунт удалён».
- Окно назначения владельцем организации проходит через окно пароля.

### Данные
Демо-данные не меняются: один демо-человек получает два устройства в списке сессий при входе — этого хватает.

## Риски
- Удаление аккаунта задевает отклики, рекомендации, приглашения, избранное, организации. Защита: одна транзакция, таблица «что куда» в тесте проверяет каждую таблицу с `user_id`.
- Новая колонка в `users` и `applications` меняет сгенерированные типы sqlc: правки во многих пакетах.
- Окно пароля на назначении владельца трогает критичную зону сайта `features/orgs` (порог 97%).
