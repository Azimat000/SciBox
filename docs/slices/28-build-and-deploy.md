# Срез 28. Сборка и выкладка

Начат 2026-10-10. Серверная очередь (D-138). Закрывает T-26 и T-27 из `docs/SECURITY.md`, затрагивает T-31, T-40, T-41, T-43, T-46, T-47, T-52, T-53.

## Цель

Сервер собирается в один образ, который можно запустить на любом виртуальном сервере с Docker; боевая конфигурация (Caddy с HTTPS, две копии сервера, воркер, база, антивирус) поднимается одной командой на Mac с самоподписанным сертификатом; обновление идёт без простоя и откатывается; резервные копии базы (с точностью до минут) и файлов восстановимы, и это проверяется командой.

## Решения пользователя в этом срезе

- Точность копий базы: несколько минут (непрерывный архив журнала изменений) — D-184.
- Срок хранения копий: 30 дней — D-185.

## Задачи

### Сервер (Go)
- Секреты из файлов (`*_FILE`): `DATABASE_URL`, `SCIBOX_S3_SECRET_KEY`, `SCIBOX_S3_ACCESS_KEY`, `SCIBOX_SMTP_PASSWORD`, `SCIBOX_OPS_TOKEN`, `SCIBOX_ERROR_DSN`.
- Команда `scibox healthcheck` для проверки контейнера (в distroless нет оболочки и curl).
- Тест безопасности миграций для выкладки без простоя (расширить-потом-сжать).

### Образ и сборка
- `Dockerfile`, `.dockerignore`, сборка сайта внутри, образ базы с pgBackRest, образ резервного копирования.

### Развёртывание
- `deploy/docker-compose.prod.yml`, `deploy/Caddyfile`, `deploy/docker-compose.local.yml` (репетиция на Mac), скрипты `deploy/*.sh`, шаблон окружения, мониторинг в бою (профиль).

### Проверка
- Образ: trivy. Конфигурация: `docker compose config`. Живой стенд: e2e, выкладка новой версии под нагрузкой (`k6`), откат, `make restore-check`.

## Риски

- Docker Hub из РФ может быть недоступен: все образы параметризованы, зеркала в `docs/DEPLOY.md`.
- Память Docker на Mac 3,8 ГБ: полный ClamAV (2 ГБ) на Mac не поднимается; в репетиции облегчённый.
- pgBackRest по протоколу S3 работает только поверх TLS: в репетиции хранилище стоит за Caddy с самоподписанным сертификатом.
- `make share` остаётся для показа.
