# Срез 28: differential-review изменений в критичных зонах

Метод: `differential-review` по своим правкам (`config`, `cli`, `migrate`, `deploy/`), от коммита среза 27 (`73c8eeb`). Размер: средний, правки в основном добавляют код; удалений защитного кода нет. Уверенность: высокая для Go-кода (всё покрыто тестами, имена ниже), средняя для скриптов оболочки (проверены на живой репетиции, но без отдельного набора тестов).

## Что менялось в критичных зонах

## Рассмотренные сценарии нападения

1. **Подмена пути секрета** (`X_FILE=/etc/passwd`): путь задаёт администратор окружением процесса; посетитель на него не влияет. Если окружение скомпрометировано, нападающему и без этого доступны сами секреты. Символьная ссылка: проверка прав идёт по открытому дескриптору (`f.Stat()`), а не по пути. Не требует исправления.
2. **Утечка значения секрета в журнал или отчёт об ошибке**: сообщения содержат только имя переменной и путь (`TestSecretFileProblemsStop…`: значения `TOP-SECRET-VALUE`, `from-file`, `inline` в тексте ошибки не встречаются).
3. **Тихая подмена секрета значением по умолчанию**: `X_FILE`, указанный пробелами, считается незаданным (как и везде в настройках), после чего действуют проверки боевого режима: пароль и ключи разработки отвергаются (`TestProductionAcceptsAllSecretsFromFiles`), секрет внутреннего порта обязателен при порте в чужой сети. Принято.
4. **Обход защиты `seed` через переменную окружения посетителя**: окружение процесса посетителю недоступно. Принято.
5. **`release` в боевом режиме выполняет миграции вперёд без подтверждения**: это и есть его назначение; миграции после 00024 только добавляют (`TestNewMigrationsOnlyExpandTheSchema`), откат миграций командой отказывает без разрешения.
6. **Доступ из соседнего контейнера к `/metrics` и `/readyz`**: `/readyz` без секрета (ответ «ok/fail» без текста), `/metrics` с секретом (`opsserver.TestSecretGuardsMetricsAndProfiles`). Сеть `backend` не публикуется, `edge` содержит только Caddy и копии (`TestProdComposeOnlyCaddyListensOnThePublicNetwork`).
7. **Суперпользователь базы из сети**: `pg_hba.conf` пишет initdb: из сети только роль `scibox` по TLS, остальное `reject`; роль без прав суперпользователя (проверено на восстановленной базе: `rolsuper = f`).

## Находки

| № | Серьёзность | Что | Решение |
|---|---|---|---|
| 1 | низкая | Временный том `restore_scratch` проверки восстановления содержит копию базы с персональными данными, если процесс проверки убит посередине (обычно скрипт стирает каталог при выходе) | записано в `docs/DEPLOY.md` (раздел 9): после прерванной проверки `docker volume rm scibox-prod_restore_scratch` |
| 2 | низкая | `gosu` в официальном образе PostgreSQL собран старым Go: 25 находок стандартной библиотеки (в `trivy`), недостижимы (сети не слушает, только отдаёт права) | принята (T-54), CI пропускает файл `gosu` и проверяет остальное образа |
| 3 | информационная | Один и тот же `docker build` даёт образу новый номер (время сборки), и compose перезапускал базу при каждой выкладке | исправлено: имя образа базы содержит отпечаток содержимого `deploy/postgres` (`deploy/db-image-tag`); проверено на репетиции (два раза подряд, база не перезапускалась) |
| 4 | информационная | Копия сервера, поднятая раньше Caddy, могла занять его фиксированный адрес в сети `edge` | исправлено: `ip_range` в верхней половине подсети |

Открытых находок нет.
