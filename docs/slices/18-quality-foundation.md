# Срез 18: Фундамент качества

Статус: в работе. 2026-10-08.

## Цель
Версия Go закреплена за проектом и без известных уязвимостей, линтер чист, `make test` сам запускает линтер и проверку уязвимостей, при отправке в GitHub всё проверяется автоматически.

## Задачи
### Сервер
- `toolchain go1.26.6` в `server/go.mod` (T-01).
- Разобрать все замечания `make lint` (T-02): настоящие исправить (G115, `%w`, `errors.Is`, `Close` у записи), ложные пометить `//nolint:правило // причина`. Каждое изменение поведения сопровождается тестом.
- Добавить в `.golangci.yml` `gocritic` (только диагностические проверки) и `revive` (правила об ошибках и экспорте), снова до нуля; `nolintlint` следит, чтобы у каждого `//nolint` были правило и причина.
- `make lint` и `make vulncheck` внутри `make test`.
### CI (T-03)
- `.github/workflows/ci.yml`: сервер (PostgreSQL сервисом GitHub, `go test -race` с порогами), сайт (typecheck, oxlint, vitest с порогами), линтер, govulncheck. Минимальные права, закреплённые версии.
- `.github/dependabot.yml`: Go, npm (`web`, `e2e`), GitHub Actions.

## Готово, когда
- [ ] `make lint` = 0 замечаний
- [ ] `make vulncheck` без находок на путях кода
- [ ] `make test` зелёный и включает обе проверки
- [ ] файлы CI лежат в репозитории (зелёный прогон на GitHub — если пользователь разрешит отправку)

## Риски
- Правки ради линтера меняют поведение (каждую сопровождает тест).
- CI без Docker Hub: PostgreSQL берётся сервисом GitHub.
