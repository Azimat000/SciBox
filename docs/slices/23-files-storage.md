# Срез 23. Файлы: хранилище S3, проверка на вирусы, потоковая загрузка

Начат 2026-10-09. Серверная очередь (D-138). Закрывает T-21 из `docs/SECURITY.md`.

## Цель

Файлы откликов и писем рекомендателей лежат не в базе, а в S3-совместимом хранилище; загрузка идёт потоком (в памяти не больше порции файла); каждый файл проверяется ClamAV, и организация получает только проверенные; заражённый не принимается; сбой антивируса или хранилища не пропускает файл и не теряет его.

## Что было до среза (проверено по коду)

- `application_files.data bytea`; `files.ReadForm` читал каждый файл в память целиком (до 6 × 10 МБ на запрос плюс копии при записи в базу и при выдаче).
- Проверка вида файла: метка `%PDF-` в первом килобайте, после того как файл уже прочитан.
- Выдача: `Service.File` читал `data` из базы и отдавал целиком; в архив выгрузки (`dataexport`) файлы шли тоже из `data`.
- Стирание аккаунта удаляло строки `application_files`.
- Вирусной проверки не было.

## Решения среза (записать в DECISIONS)

1. **Хранилище.** Интерфейс `blobstore.Store` (Put потоком, Get, Delete, Walk, Ping); боевая реализация на `minio-go` (работает с любым S3: Yandex, Selectel, VK Cloud; `PathStyle` для локального), `Memory` для тестов. MinIO убран из Docker Hub и Quay (проверено 2026-10-09), локально SeaweedFS 4.48 (Apache-2.0).
2. **Выдача только через сервер.** Не подписанные ссылки: право, запись в журнал (I-33) и заголовки защиты остаются в одном месте; ссылку нельзя переслать.
3. **Проверка на вирусы.** Сразу при загрузке (до 20 секунд); заражённый отклоняется с сообщением, объект удаляется; антивирус недоступен — файл принимается со статусом «на проверке» и недоступен организации, пока фоновая задача его не проверит. Ничего не пропускается и не теряется.
4. **Миграция без простоя.** `00019` добавляет колонки, `data` переименовывается в `legacy_data` и больше не заполняется; фоновая задача переносит старые файлы в хранилище, сверяя SHA-256 после чтения обратно, и обнуляет `legacy_data`. Колонка удаляется в срезе 28.

## Задачи

### Сервер
1. `blobstore`, `antivirus` (clamd по TCP, INSTREAM), склад `files.Vault` (приём потоком, проверка по первым байтам до записи, контрольная сумма, проверка вирусов).
2. Миграция `00019`; запросы sqlc; `applications`, `references`, `dataexport`, `erasure` переведены на хранилище.
3. Фоновая задача `filework`: проверка файлов «на проверке», перенос старых файлов, чистка осиротевших объектов (старше суток, нет строки в базе).
4. Настройки `SCIBOX_S3_*`, `SCIBOX_CLAMAV_ADDR`; боевой режим не принимает http-хранилище, ключи из docker-compose и отключённый антивирус.
5. Демо-данные через склад.

### Интерфейс
- Метки «Проверяется» и «Не прошёл проверку» у файлов в карточках отклика, сообщение об инфицированном файле в форме отклика и письма рекомендателя. Тексты в `ru.ts`.

### Данные
- Демо-файлы (PDF) уходят в хранилище через склад.
