# Срез 5: справочники и вакансии

Статус: готов. 2026-10-03.

## Цель
Организация может создать вакансию (черновик), опубликовать, закрыть и убрать в архив; у вакансии есть публичная страница; сотрудник видит «Мои вакансии» по своим правам; на страницах организации и подразделения вместо пустого места список опубликованных вакансий. Справочники (специальности ВАК, регионы, должности и т.д.) лежат в базе, источники записаны.

## Решения (записаны в DECISIONS, D-053…D-063)
- Справочники: большие (специальности, регионы, должности) в таблицах БД, загружаются миграцией из официальных источников; маленькие перечисления (уровни R1–R4, форматы, финансирование, степени…) — значения в коде сервера (CHECK в БД), подписи в `ru.ts`. Источники: `docs/REFERENCE.md`.
- Должность (`positions`) задаёт тип позиции (научная / ППС / аспирантура–постдок / управление).
- Вакансия живёт в пакете `internal/vacancies` (критичная зона 97%); права только через `access.ManageVacancies`.
- Жизненный цикл: черновик → опубликована → закрыта → архив; таблица переходов проверяется целиком.
- Подразделение с вакансиями удалить нельзя (внешний ключ RESTRICT, ошибка 409 `unit_has_vacancies`).

## Задачи

### Сервер
1. Миграции: `00004_reference.sql` (таблицы справочников + данные), `00005_vacancies.sql` (вакансии, специальности вакансии).
2. Пакет `internal/refdata`: чтение справочников, `GET /api/reference`.
3. Пакет `internal/vacancies` (критичная): проверки полей по типу, черновик/публикация, переходы статусов, права, «Мои вакансии», публичные списки, лимит создания.
4. `orgs`: экспорт `ActorOf`, ошибка «в подразделении есть вакансии».
5. Демо-данные: вакансии для демо-организаций.
6. Тесты вместе с кодом: таблицы «кто → что», таблица статусов, сбои базы по очереди, валидация по типам.

### Интерфейс
1. `/my-vacancies` (вкладки по статусам, действия), `/my-vacancies/new`, `/my-vacancies/:id/edit` (форма с блоками по типу).
2. `/vacancies/:id` — публичная страница вакансии («статья журнала»).
3. Списки вакансий на страницах организации и подразделения.
4. Тексты в `ru.ts`; состояния: пусто, загрузка, ошибка, длинные данные, нет прав.

## Что проверяем
Путь в браузере: вход владельцем → «Мои вакансии» → новая вакансия каждого из четырёх типов → черновик → публикация → страница вакансии → закрытие → архив; руководитель подразделения видит только свои; посторонний не видит черновик.

## Риски
- Объём большой; фильтры и поиск не трогаем (срез 6).
- Данные справочников большие (≈ 400 специальностей): сверять с первоисточником, не придумывать.

## Сделано

Справочники
- Миграция `00004_reference.sql`: 35 групп и 350 действующих специальностей ВАК, 89 субъектов РФ, 27 должностей с типом, таблица источников. Данные ВАК разобраны программой из полного текста приказа № 118 на «Гарант» (исследователи не смогли открыть первоисточники; их списки по областям 3 и 5 сверены, расхождения учтены). Источники и способ: `docs/REFERENCE.md`.
- `GET /api/reference` (пакет `internal/refdata`).

Сервер (`internal/vacancies`, критичная зона)
- Миграция `00005_vacancies.sql`: `vacancies`, `vacancy_specialties`, представление `vacancy_view`; подразделение с вакансиями не удаляется (`ON DELETE RESTRICT`, ответ 409).
- Создание (черновик), правка, смена статуса по таблице переходов, удаление черновика; публикация проверяет готовность по типу позиции; публичный список; «Мои вакансии» с числом по статусам; «куда можно создать»; лимит 100 в сутки.
- `orgs.ActorOf` вынесена наружу; права на вакансии только через `access.ManageVacancies`.
- Демо-данные: 26 вакансий в 8 организациях.

Интерфейс (`features/vacancies`)
- `/my-vacancies` (вкладки со счётчиками, страницы по 50), `/my-vacancies/new` и `/:id/edit` (форма по типам позиции, выбор до пяти специальностей, регион с поиском), `/vacancies/:id` (страница-статья, управление для сотрудников), списки опубликованных вакансий на страницах организации и подразделения.

## Отступления от плана
- Исследователи (`web-researcher`) не смогли получить списки специальностей: сайты с приказом закрыты для их инструментов; один из них по ошибке отказался искать, приняв правило «делегируй» за свою задачу. Данные получены программой из «Гаранта» (см. REFERENCE.md); исследователи пригодились для регионов, должностей и проверки областей 3 и 5.
- Не включены в справочник: федеральный округ региона (не подтверждён первоисточником и не нужен), докторантура и ординатура (D-006 их не называет).
- Добавлено сверх плана: публичный `GET /api/vacancies` (основа поиска), лимит создания, «куда можно создать вакансию», перенос вакансии между подразделениями.
- Поле «Тип позиции» не хранится: тип даёт должность (D-054).

## Проверки
- `make test`: зелёный (сервер и сайт, пороги покрытия).
- Один раунд во встроенном браузере (компьютер 1440 и телефон 375): вход владельцем, «Мои вакансии», создание черновика, «Опубликовать» с неполной вакансией (понятный список недостающего), дополнение через форму и публикация, страница вакансии, списки на странице организации. Руководитель подразделения: проверено запросами к серверу (видит только своё подразделение там, где он руководитель, и всё там, где он кадровик). Исправлено по итогам: подпись под уровнем R1–R4 вместо обрезанных пунктов списка, пробел между кодом и названием специальности, срок не повторяется среди условий у опубликованной вакансии, порядок недостающих полей как в форме.
- `break-ui`: вакансия с названием 200 знаков и словом без пробелов, аннотацией из длинных слов, пятью специальностями, суммой до 99 999 999, примечанием к гранту 150 знаков: горизонтальной прокрутки нет на телефоне ни на странице вакансии, ни в списке, ни в «Мои вакансии».
- `impeccable detect` по `features/vacancies`, `ui`, `features/orgs`: замечаний нет.
- Не делалось: `/impeccable critique` и `web-design-guidelines` отдельным проходом (долг перешёл из срезов 3–4, см. HANDOFF).
