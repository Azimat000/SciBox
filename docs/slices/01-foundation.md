# Срез 1. Фундамент проекта

Дата: 2026-10-02. Статус: готов.

## Цель
Пустой, но работающий скелет: сервер на Go с базой PostgreSQL, сайт на React, общая команда запуска и тесты с порогами покрытия. Страница показывает, что сервер и база отвечают.

## Задачи

### Продукт
- `/impeccable init` → `PRODUCT.md` (секция `## Stack` из D-017, D-018).

### Сервер (`server/`)
- Go-модуль, chi, pgx/v5, sqlc (через `go tool`), goose (как библиотека, миграции встроены в бинарник).
- Конфиг из переменных окружения, включая название продукта.
- Первая миграция (служебная таблица `app_meta`), запрос sqlc к ней.
- `GET /api/health`: проверяет БД, отдаёт название продукта и версию схемы. Единый формат ошибок API.
- Команды бинарника: `serve`, `migrate up|down|status`.
- Тесты с настоящей PostgreSQL в Docker (отдельная база `scibox_test`).

### Интерфейс (`web/`)
- Vite + React + TypeScript, React Router, TanStack Query, словарь `ru.ts`.
- Название продукта в одной настройке (`config/product.json`), общей для сервера и сайта.
- Стартовая страница: статус сервера и базы (загрузка / работает / ошибка), страница 404.
- Vitest + Testing Library + coverage-v8 с порогами.

### Окружение
- `docker-compose.yml`: PostgreSQL 16 (порт 5433, т.к. 5432 занят локальной PostgreSQL), Mailpit (8025/1025).
- `Makefile`: `dev`, `test`, `seed`, `migrate`, `db-reset`.
- `scripts/coverage-check`: пороги покрытия Go.

## Что проверяем
- `make dev` поднимает базу, сервер и сайт; страница открывается и показывает «сервер работает».
- `make test` зелёный и падает при покрытии ниже порога.
- Миграции: накат на пустую базу → откат → накат.

## Риски
- Порт 5432 занят локальной PostgreSQL → используем 5433.
- sqlc собирается из исходников при первом запуске (cgo), может занять пару минут.
- Визуальный стиль ещё не выбран (срез 2): стартовая страница нарочно простая, без дизайн-системы.

## Сделано
- `PRODUCT.md` через `/impeccable init`: три вопроса пользователю (главный пользователь, отличие, тон), остальное из DECISIONS (D-027).
- `docker-compose.yml`: PostgreSQL 16.15 на 5433, Mailpit v1.31.3. Версии взяты из самих образов (`postgres --version`, `mailpit version`) и закреплены.
- Сервер: команды `serve`, `migrate up|down|reset|status`, `seed` (пока заглушка с честным сообщением), `version`; `GET /api/health`; единый формат ошибок (D-032); логирование запросов; перехват паник с JSON-ответом 500; мягкая остановка.
- Миграция `00001_extensions.sql` (citext, pg_trgm); запрос sqlc `ServerVersion`.
- Сайт: Vite 8, React 19, React Router 8, TanStack Query 5. Временная стартовая страница со всеми состояниями (проверяем / работает / база недоступна / сервер не отвечает / непонятный ответ), 404, страница падения. Все тексты в `src/i18n/ru.ts`. Название продукта из `config/product.json` и в шапке, и в `<title>`.
- Тестовая инфраструктура: `internal/testdb`, `scripts/coverage-check` + `server/coverage.conf`, Vitest с порогами; `make test` гоняет `go vet`, тесты сервера, `tsc`, `oxlint`, тесты сайта.
- `.claude/launch.json` для встроенного браузера (`make dev`).

## Отступления от плана
- Служебной таблицы `app_meta` нет: первая миграция ставит расширения, которые точно понадобятся в срезах 3 и 6. Версию схемы `/api/health` берёт у goose.
- Встроенный браузер не смог сам запустить `make dev` (macOS не пускает его в папку «Документы»: `getcwd: Operation not permitted`). Сайт запускался через терминал, браузер подключался к адресу.
- `/impeccable audit` и `critique` не запускались полностью: страница временная и заменится в срезе 2 (D-034). Вместо этого проверены контраст, фокус с клавиатуры и состояния.

## Проверки
- `make test`: зелёный.
- Пороги действительно роняют проверку: сервер с порогом 99% → exit 1; непокрытый файл на сайте → `vitest` exit 1.
- Миграции: накат на пустую базу → откат → накат → reset → накат (тест `TestUpDownUp`).
- `make dev`: сервер и сайт поднялись, `/api/health` отвечает и напрямую, и через прокси Vite, `<title>` = SciBox.
- Браузер, 1440 и 375: стартовая и 404 без переполнений. База остановлена (`docker compose stop postgres`) → «Сервер отвечает, база недоступна» + подсказка; база запущена → «Проверить ещё раз» → «Работает». В консоли только ожидаемый 503.
