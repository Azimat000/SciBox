# Срез 19. Периметр HTTP

Начат 2026-10-08. Серверная очередь (D-138). Угрозы T-04…T-09 из `docs/SECURITY.md`.

## Цель

Сервер сам защищает свою «входную дверь»: не даёт медленным клиентам держать соединения, отправляет браузеру заголовки защиты, знает настоящий адрес человека за прокси, ограничивает частоту тяжёлых публичных запросов, не читает огромные тела и отказывается стартовать в бою с опасными настройками.

## Задачи

### Сервер
1. Новый пакет `internal/httpguard` (критичная зона 97%):
   - `server.go`: `NewServer` с `ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout`, `MaxHeaderBytes` (T-04); долгие передачи (загрузка откликов и писем рекомендателей, выдача файлов и PDF) продлевают срок через `http.ResponseController`.
   - `headers.go`: заголовки защиты (T-05): CSP для сайта и для API, `frame-ancestors 'none'`, HSTS только при https, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`.
   - `realip.go`: настоящий IP (T-06): `SCIBOX_TRUSTED_PROXIES`; `X-Forwarded-For` читается справа налево, только если соединение пришло от доверенного прокси.
   - `routes.go`: одна таблица особых адресов (лимит тела, долгая передача, ограничение частоты) с проверкой, что каждый адрес таблицы есть в роутере.
   - `body.go`: лимит тела на каждом адресе (T-09): по умолчанию 1 МиБ, загрузки по таблице; `Content-Length` больше лимита — сразу 413.
   - `ratelimit.go`: ограничение частоты (T-07): гость по IP (IPv6 по сети /64), вошедший по аккаунту; 429 + `Retry-After` в формате D-032. Счётчики в PostgreSQL (таблица `rate_counters`, работает при двух копиях сервера).
2. `config`: `SCIBOX_ENV=production` (T-08) и `SCIBOX_TRUSTED_PROXIES`.
3. `apierr.DecodeJSON`: слишком большое тело даёт 413 `payload_too_large`, а не 400.
4. `auth`: IP для лимитов и сессий берётся через `httpguard.ClientIP`.
5. Миграция `00015_rate_counters.sql`, запросы sqlc, очистка старых счётчиков в фоне.
6. `scripts/share`: доверять адресу туннеля на этом Mac (`127.0.0.1`).

### Интерфейс
Экранов не меняем. Проверка: CSP не ломает сайт (главная, поиск, профиль, отклик с файлом) в сборке, которую отдаёт сам сервер.

## Риски
- CSP ломает шрифты или стили Vite. Проверка в браузере на собранном сайте.
- Лимиты мешают сквозным тестам (Playwright с одного адреса): лимиты щедрые, вошедшие считаются по аккаунту.
- Каждый ограниченный запрос пишет в базу: одна строка на ключ и минуту, таблица без журнала (UNLOGGED).
