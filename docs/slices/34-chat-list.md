# Срез 34. Чат, интерфейс 1: контракт, подставной сервер, список переписок

Начат 2026-10-14. Правила чата: `docs/CHAT.md`. Решения: D-214…D-216, раскладка списка D-217.

## Цель

Учёный и организация видят свои переписки на странице «Сообщения», число непрочитанных в шапке и попадают в переписку со страниц откликов и приглашений. Сервера чата ещё нет: интерфейс работает на подставном сервере в браузере, который отвечает строго по контракту `contracts/chat/`.

## Бриф экрана (impeccable shape)

- **Кто смотрит.** Учёный (режим «Ищу работу»): несколько переписок с организациями, чаще с телефона. Сотрудник организации (режим «Нанимаю»): десятки переписок по нескольким вакансиям, за столом.
- **Главная задача.** Понять, где ждут ответа, и открыть нужную переписку. Новое всегда сверху.
- **Раскладка.** Вариант А «как в почте» (выбор пользователя, D-217): строка из трёх линий: собеседник и время; вакансия и состояние отклика; начало последнего сообщения и число непрочитанных. Макеты: `.impeccable/mocks/chat/`.
- **Состояния.** Загрузка (заготовки строк), пусто (свой текст учёному и организации, отдельно для «Непрочитанных», «Архива» и поиска без результатов), ошибка с повтором, нет входа (на вход и обратно), длинные названия, имя скрыто, 99+ непрочитанных.
- **Телефон.** Только список; переписка открывается отдельным экраном с возвратом к списку.
- **Не трогаем.** Страницы откликов и приглашений: только добавляется кнопка входа в переписку.

## Задачи

- Контракт: `contracts/chat/*.json` на каждый адрес из `CHAT.md` и каждый вид системной строки, перечни допустимых значений `enums.json`; проверка «по полям и типам» на стороне сайта; типы `web/src/features/chat/api.ts`; таблица адресов в `CHAT.md` по примерам.
- Подставной сервер `web/src/features/chat/mock/`: адреса контракта, демо-переписки обеих сторон (разговор, приглашение ждёт ответа, отказ, анонимный соискатель, архив), входящие сообщения, «печатает», прочтение, живой поток; включается `VITE_CHAT_MOCK=1` только в разработке, динамическим импортом. Тест сборки: в боевой сборке его нет (T-104).
- Страница `/chats` (и `/chats/:id` с заглушкой окна): вкладки, поиск, отбор по вакансии у организации, «Показать ещё», все состояния, две колонки на компьютере, одна на телефоне.
- Значок «Сообщения» с числом непрочитанных в шапке (опрос раз в минуту).
- Кнопки «Написать» / «Перейти к переписке»: отклик (обе стороны), «Мои отклики», «Отклики» организации, приглашения на вакансию (учёный и организация).

## Риски

- Подставной сервер дописывает поле `chat` в ответы настоящего сервера откликов и приглашений: если сервер изменит эти ответы, подставной слой может их испортить. Слой только добавляет поле и удаляется в срезе 39.
- Человек в двух ролях: переписки делятся по стороне (`side`), число в шапке общее.

## Сделано

- **Контракт** `contracts/chat/`: README (формат и правила сверки), `enums.json`, `errors.json` (12 ошибок), файл на каждый адрес из CHAT.md (список, число непрочитанных, вакансии для отбора, шапка, лента, отправка, правка, удаление, прочтение, архив, «печатает», живой поток, шаблоны ×4, блокировка ×3, жалоба, настройки писем) и `links.json` (поле `chat` у откликов и приглашений). Сверка «по полям и типам» `web/src/test/contract.ts`: форма из всех примеров, перечни, виды по полю (`variants`), словари (`maps`). Таблица адресов в CHAT.md переписана по примерам.
- **Решения контракта (Claude):** список просят по стороне `side` (человек бывает и учёным, и сотрудником); число в шапке — переписки с непрочитанным обеих сторон (`{total, scientist, org}`); новый адрес `GET /api/chats/vacancies` для отбора; сообщение в адресе правки называется `seq`; у сообщения `editable_until` вместо флагов; своё сообщение тоже приходит событием потока; поле `chat{id, unread, can_write, started}` вместо `chat_id`; подпись анонимного — «Анонимный соискатель» (D-199, D-135).
- **Подставной сервер** `web/src/features/chat/mock/`: все адреса контракта в памяти браузера, 10 демо-переписок (по 5 у каждой стороны: разговор, приглашение ждёт ответа, приглашение на вакансию, отказ, отзыв, анонимный соискатель, ушедший сотрудник, архив), «входящие» раз в 40–70 секунд с «печатает», прочтение через 2 секунды после отправки, живой поток SSE с повтором после `Last-Event-ID`, хранение в `localStorage`. Дописывает поле `chat` в ответы настоящего сервера откликов и приглашений и хранит `email_messages`. Наборы для проверки: `?data=worst|empty|many` с переключателем внизу экрана. Включается `VITE_CHAT_MOCK=1` только в разработке (`main.tsx`, динамический импорт).
- **Страница «Сообщения»** `/chats/:id?`: вкладки «Все / Непрочитанные / Архив» с числами, поиск (пауза 300 мс или Enter), у организации отбор по вакансии, строки «как в почте», «Показать ещё» (ключ листания), подсказка о непрочитанном в другом режиме с переключением, состояния загрузки, пусто (у каждой стороны и вкладки свой текст), ошибки и повтора, ничего не найдено. Справа заглушка «Выберите переписку», у открытой переписки шапка (собеседник, вакансия, состояние, «Открыть отклик / приглашение», причина закрытия) — лента в срезе 35. На телефоне список и переписка по очереди.
- **Шапка:** значок «Сообщения» с числом (опрос раз в минуту). Чтобы шапка соискателя поместилась, значки собраны группой и промежутки уменьшены (D-218).
- **Кнопки входа** `ChatButton` на шести страницах: «Написать» / «Перейти к переписке» с числом новых.

- `impeccable detect` по папке чата: 0 замечаний.
- **break-ui** (строка списка; набор `?data=worst`: название организации 200 знаков, вакансия 200, имя 120, 1500 и 12345 непрочитанных, кириллица с латиницей, вьетнамский, китайский, апостроф, сообщение из 4000 одинаковых букв, длинная ссылка, только переносы строк, год назад; `?data=empty`, `?data=many` — 1000 строк у каждой стороны). Выдержали: числа 99+, многоточие у вакансии и сообщения, смешанные алфавиты, пустой текст, неизвестное событие и статус, 1000 строк (страницы по 30).
