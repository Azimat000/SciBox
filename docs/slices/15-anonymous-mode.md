# Срез 15. Анонимный режим и «скрыть от моей организации»

Начат 2026-10-11. Решения D-199…D-205 (записаны в `docs/DECISIONS.md`). Продуктовая очередь, первый срез после серверной (D-138).

## Цель

Две новые возможности приватности профиля учёного:
1. **Режим «Анонимно для организаций»**: сотрудники организаций видят научные данные (степень, звание, уровень R, специальности, h-index, счётчики публикаций и статей Q1–Q2), но не имя, не место работы, не город и регион, не идентификаторы, не названия публикаций и грантов, не контакты. Имя открывается организации, когда учёный сам откликнулся на её вакансию или ответил «Интересно» на её приглашение. Анонима можно приглашать.
2. **«Скрыть от организаций»**: учёный выбирает организации, чьи сотрудники не видят профиль ни в каком режиме.

## Карта мест, где профиль уходит наружу (риск среза)

| Место | Что было | Что делаем |
|---|---|---|
| Страница учёного `GET /api/scientists/{id}` | всё, что положено по режиму | по уровню раскрытия: нет / анонимно / полностью |
| Резюме PDF `GET /api/scientists/{id}/cv` | всё | только при полном раскрытии |
| Каталог `GET /api/scientists` | карточка с именем | анонимная карточка; анонимы не находятся по словам и региону, не сортируются по имени |
| Приглашение: проверка «профиль виден» | `CanView` | видимый аноним можно приглашать, скрытый от организации нельзя |
| Приглашение: ответ организации (`Offer.Scientist`, список «Отправленные») | имя | имя только если режим не анонимный или имя раскрыто |
| Уведомление и письмо сотрудникам «Ответил …» | имя | то же правило |
| Журнал действий организации (`subject` у `offer.sent/canceled`) | имя и номер аккаунта | у скрытого аноним: «Кандидат», без номера |
| Отклик (снимок профиля, D-079) | имя | без изменений: человек откликнулся сам; заодно имя раскрывается организации |
| Числа главной | профили публичного режима | без изменений (аноним не публичен) |
| Выгрузка своих данных, удаление аккаунта | — | новые таблицы входят в выгрузку и стираются каскадом |

## Задачи

### Сервер
- [ ] Миграция 00027: режим `anonymous` в `profiles.visibility` (и `visibility_before_deletion`), таблицы `profile_hidden_orgs` и `profile_reveals`.
- [ ] `privacy`: режим `Anonymous`, уровень раскрытия `None/Anonymous/Full`, `Viewer.Blocked/Revealed`; таблица «кто × режим × скрыт ли × раскрыт ли».
- [ ] `profiles`: анонимный вид страницы, резюме только полному, каталог (SQL: скрытость, раскрытие, поиск), список «скрыто от», добавить и убрать организацию (до 50).
- [ ] `applications`: раскрытие имени при отправке отклика.
- [ ] `offers`: приглашение аноним/скрытому, раскрытие при «Интересно», имя в списках и уведомлениях.
- [ ] `audit`: аноним в журнале.
- [ ] Демо-данные: анонимные профили, скрытые организации, раскрытие.

### Интерфейс
- [ ] Панель приватности: четвёртый режим, блок «Скрыть от организаций» (поиск организации, список, убрать).
- [ ] Анонимная карточка в каталоге и на странице учёного; без «Скачать резюме»; пояснение «имя откроется, когда…».
- [ ] Окно приглашения и «Отправленные приглашения» для анонима; тексты в `ru.ts`; пустые/загрузка/ошибка.

## Что проверяем
- Табличные тесты `privacy` и сквозные: те же пары через базу (страница, каталог, приглашение, резюме) дают тот же ответ.
- Утечка имени: ни в одном ответе, письме, уведомлении, журнале, CV.
- `make lint-new` 0, `make vulncheck`, `differential-review`, `break-ui`, `impeccable audit`.

## Готово, когда (из ROADMAP)

- [ ] «Скрыть от организаций»: выбранные организации не видят профиль ни в каком режиме.
- [ ] Всё через `privacy` (≥ 97%), табличные тесты на каждую пару.
- [ ] Каталог, страница, приглашение: анонимная карточка, анонима приглашать можно.
- [ ] Проверены все места утечки (таблица выше).
