# Срез 32: ссылка на GitHub в профиле

Статус: готов (2026-10-14, метка `slice-32`). Решения: D-199…D-202 (анонимный профиль), D-186 (миграции только добавляют). Скиллы: golang-security, golang-testing, property-based-testing, sharp-edges, differential-review, impeccable.

## Цель
Поле «GitHub» среди идентификаторов профиля. Человек вводит `github.com/логин` или `https://github.com/логин`, в базе лежит `https://github.com/<логин>`. Проверка строгая и без обращений в сеть.

## Задачи
Сервер
- миграция 00029: столбец `profiles.github_url` (только добавление, `DEFAULT ''`, длина ≤ 60);
- запрос `UpdateProfileCore`, `sqlc generate`;
- разборщик ссылки `profiles/github.go` (ручной разбор строки, без `net/url`), сообщения по полю `github_url`;
- `CoreInput.GitHubURL`, `Identifiers.GitHubURL`, `build`, `SaveCore`;
- резюме PDF: строка «GitHub» среди идентификаторов;
- безымянная карточка: поля нет (список разрешённого `blindView`, тест);
- снимок отклика, выгрузка данных, карта ПДн, стирание: проверить и покрыть тестами.

Интерфейс
- форма профиля: поле «GitHub» в блоке идентификаторов;
- страница профиля: ссылка в новой вкладке, `rel="noopener noreferrer nofollow"`, подпись `github.com/логин`;
- тексты в `web/src/i18n/ru.ts`.

Данные: у части демо-людей вымышленные логины.

## Проверяем
- таблица допустимых и недопустимых ссылок (юнит-тест) и фаззинг разборщика (инварианты: результат всегда `https://github.com/<логин по правилам>`; повторный разбор результата даёт то же);
- круг «ввод → база → ответ → резюме → снимок отклика → выгрузка»;
- анонимная карточка поле не получает;
- `cli.TestErasedPerson...` ищет метку GitHub после стирания.

## Риски
- Разборщик ссылок легко сделать дырявым (sharp-edges): поэтому строка разбирается вручную по списку разрешённого, `net/url` не используется.
- Профиль в безымянной карточке: поле не должно утекать через любой новый путь (проверка тестом по всему JSON).

## Готово, когда
- [x] таблица допустимых и недопустимых ссылок (`github.com.evil.ru`, `evil.ru/github.com/x`, `https://github.com@evil.ru`, `github.com:8080`, `javascript:`, `data:`, юникодные двойники, пробелы и переводы строк) проходит тестом и фаззингом;
- [x] поле видно в профиле, резюме и выгрузке данных;
- [x] невидимо в анонимной карточке;
- [x] `make test` зелёный.

## Сделано
- Миграция `00029_profile_github.sql`: `profiles.github_url`, только добавление; `UpdateProfileCore` и `sqlc` пересобраны.
- `profiles/github.go`: `normalizeGitHub` (ручной разбор по списку разрешённого, три причины отказа), `validGitHubLogin`; сообщения по полю `github_url` в `validateCore`.
- `CoreInput.GitHubURL`, `Identifiers.GitHubURL`, `build`, `SaveCore`; в резюме PDF строка «GitHub» (`github.com/логин`); безымянная карточка поля не получает.
- Сайт: поле в форме профиля, ссылка в «Идентификаторы и метрики» (новая вкладка, `rel="noopener noreferrer nofollow"`), `githubLogin` проверяет значение перед `href`, тексты в `ru.ts`.
- Демо-данные: у двух учёных вымышленные логины `scibox-demo-…`.
- Память: D-210, I-107, T-90 (закрыта), T-91 (принята), карта ПДн, ARCHITECTURE, DOMAIN, TESTING; разбор правок: `32-differential-review.md`.

## Проверки
- `make test` зелёный целиком: линтер 0 замечаний, `govulncheck` без находок в коде, сервер с порогами, сайт 1014 тестов (было 993).
- Фаззинг `FuzzNormalizeGitHub`: 20 секунд, ≈900 тысяч запусков без находок; запасные примеры входят в обычный прогон.
- Таблицы: 16 допустимых и 74 недопустимых ссылки (в том числе все из задания) плюс перебор 10 тысяч сочетаний кусочков с проверкой инварианта.
- Круги: ввод → база → страница → резюме → снимок отклика (не меняется вместе с профилем) → выгрузка данных → стирание (`cli.TestErasedPerson…` ищет и эту метку).
- Браузер (встроенный, 1440 и 375): отказ под полем, сохранение с нормализацией, ссылка в блоке идентификаторов; худший случай (логин из 39 знаков на 375 пикселях) не вылезает за экран.
