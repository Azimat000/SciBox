# Масштабирование и производительность сервера

Живой документ серверной очереди (срезы 18–29, D-138). Здесь цели в цифрах, правила, которые держат сервер масштабируемым, и замеры по срезам. Срез, который что-то измерял, дописывает строку в «Замеры»; цифры без даты и условий не пишутся.

| Показатель | Цель |
|---|---|
| Пик | 500 запросов в секунду на смеси «поиск вакансий, страница вакансии, соискатели, главная, вход, отклик» |

## Правила, которые держат сервер масштабируемым

1. Сервер без состояния в памяти: сессии, лимиты, очереди, блокировки живут в PostgreSQL. Любой запрос может прийти в любую копию.
2. Фоновые задачи безопасны при нескольких копиях: строки берутся `FOR UPDATE SKIP LOCKED` или под рекомендательной блокировкой (advisory lock); повтор задачи не создаёт дублей.
3. Каждый список ограничен: пагинация с максимальным размером страницы; на больших таблицах листание по ключу, а не `OFFSET`.
4. У каждого запроса к базе и внешнему сервису есть срок (`context` с таймаутом, `statement_timeout`).
5. Горячие запросы проверены `EXPLAIN (ANALYZE, BUFFERS)` на объёме из таблицы выше; без последовательного чтения больших таблиц.
6. Файлы не проходят через память целиком и не лежат в базе (после среза 23).
7. Справочники и числа главной кешируются на короткий срок.
