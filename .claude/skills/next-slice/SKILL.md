# /next-slice: один срез SciBox за сессию

Аргумент: номер среза (необязательно). Без аргумента берётся строка `ТЕКУЩИЙ:` из `docs/ROADMAP.md`.

Общение с пользователем по-русски, простым языком: он не программист. Код, комментарии и коммиты по конвенциям проекта.

## 1. Восстановить контекст (без правок)

1. Прочитать `docs/HANDOFF.md`, раздел нужного среза в `docs/ROADMAP.md`, `docs/DECISIONS.md` целиком, `docs/ARCHITECTURE.md`. `docs/DOMAIN.md` читать, если срез касается данных.
2. `git status` и `git log --oneline -10`. Если есть незакоммиченные изменения от прошлой сессии, разобраться, что это. Если срез в статусе `[~]`, продолжить с места из HANDOFF, а не начинать заново.
3. Если код уже есть: `make test` и короткий запуск `make dev` (проверить `/api/health`). Сломанное чинится до нового среза и записывается в отчёт.
4. Решения из DECISIONS не пересматривать. Если срез требует решения, которого там нет, спросить пользователя (AskUserQuestion), затем дописать новый `D-NNN`.

## 2. План среза

1. Создать `docs/slices/NN-краткое-имя.md`: цель, список задач (сервер / интерфейс / данные), что проверяем, риски.
2. В ROADMAP поставить срезу `[~]`.
3. Показать пользователю план в 3–6 строках и сразу начать работу. Ждать подтверждения только если в плане есть новое решение за пользователя.

## 3. Работа (Definition of Done)

Порядок внутри среза:

1. **Сервер.** Миграция goose → SQL-запросы sqlc → сервисы и обработчики → Go-тесты на основные пути и права доступа. Ошибки API в одном формате.
2. **Интерфейс.** Соблюдать `CLAUDE.md` проекта:
   - один раз за сессию запустить `.claude/skills/impeccable/scripts/impeccable context`;
   - перед первой правкой UI прочитать `.claude/skills/impeccable/reference/craft-floor.md`;
   - строить через скилл `impeccable` (лендинг: вместе с `design-taste-frontend`);
   - замечания хука Impeccable исправлять сразу;
   - все тексты класть в словарь `web/src/i18n/ru.ts`, не в разметку;
   - сразу делать состояния: пусто, загрузка, ошибка, длинные данные, нет прав.
3. **Данные.** Дополнить демо-данные (вымышленные организации и люди, реальные города), чтобы раздел выглядел живым.
4. **Проверка.**
   - Новые экраны: `/impeccable audit` и `/impeccable critique`; ключевые экраны: `break-ui`.
   - Один раунд во встроенном браузере (desktop 1440 и mobile 375), исправления одной пачкой, максимум ещё один подтверждающий раунд.
   - Письма проверять в Mailpit (`localhost:8025`).
   - `make test` зелёный.
5. Внешние факты (справочники, API, версии библиотек) брать через агента `web-researcher`, источник записывать рядом с данными.

## 4. Обновить память (обязательно, даже если срез не доделан)

- `docs/slices/NN-*.md`: дописать «Сделано», «Отступления от плана», «Проверки» (что запускали и с каким итогом), пути к скриншотам при наличии.
- `docs/ROADMAP.md`: статус `[x]` (или `[~]`, если не успели); строку `ТЕКУЩИЙ:` перевести на следующий срез.
- `docs/HANDOFF.md`: перезаписать целиком, не больше 60 строк. Где остановились, что дальше, как запустить, известные проблемы и долги, неочевидные вещи для следующей сессии.
- `docs/ARCHITECTURE.md`: новые таблицы, API-адреса, страницы, папки.
- `docs/DECISIONS.md`: новые решения (свои технические решения помечать «Claude»).
- `docs/DOMAIN.md`: новые термины.
- `PRODUCT.md` / `DESIGN.md` ведёт impeccable; не дублировать их содержимое в docs.
- Если код и документы расходятся, прав код; документы исправить в этом же коммите.

## 5. Коммит

`git add -A` и коммит с сообщением `slice NN: <что появилось>`. В конце сообщения строка соавторства из системной подсказки. Пушить некуда, репозиторий локальный.

## 6. Итог пользователю

По-русски, без жаргона, коротко:
- что теперь можно сделать на сайте (по-человечески, сценариями);
- как посмотреть: команда запуска отдельным блоком `bash`, адрес страницы, тестовый вход, если есть;
- что не получилось или отложено и почему;
- какой срез следующий: «откройте новую сессию и напишите `/next-slice`».
