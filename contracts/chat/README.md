# Контракт API чата

Точные примеры запросов и ответов сервера чата (срез 34, D-215). Правила продукта в `docs/CHAT.md`; здесь только форма данных.

Один файл на адрес. Тесты сайта берут из них подставные ответы и сверяют с ними подставной сервер (`web/src/features/chat/contract.test.ts`). Тесты сервера (срез 37 и дальше) сверяют с ними настоящие ответы. Изменился ответ, значит в одном коммите правятся пример, тесты сайта и тесты сервера.

## Устройство файла

```json
{
  "endpoint": "GET /api/chats",
  "about": "что делает адрес",
  "query": { "side": "scientist | org, обязательно" },
  "enums": { "items[].side": "side" },
  "variants": { "items[].event": "type" },
  "errors": ["not_found", "validation"],
  "examples": {
    "имя": { "request": { "query": "...", "body": {} }, "status": 200, "response": {} }
  }
}
```

- `examples`: каждый пример настоящий ответ целиком. Пример без `response` означает ответ без тела (204).
- `enums`: строка по этому пути может быть только из перечня с этим именем в `enums.json`. Путь: ключи через точку, `[]` означает «каждый элемент массива», корень ответа без имени.
  `request_enums` то же для тела запроса (`request.body`). Имя перечня может быть объединением через `|` (`invitation_answer|offer_answer`).
- `maps`: объект по этому пути — словарь: имена полей любые (например, `error.fields`: имя поля формы → что с ним не так), значения сверяются с формой значений из примеров.
- `variants`: объекты по этому пути различаются по значению поля (например, системная строка по `type`): форма каждого вида сверяется только с примерами того же вида.
- `errors`: какие ошибки может дать адрес (коды из `errors.json`, формат ошибки общий для API, D-032).

## Как сверять «по полям и типам»

Из всех примеров файла собирается форма: у объекта набор полей (поле обязательно, если есть во всех примерах этого объекта), у поля набор типов JSON (`null`, строка, число, логическое, массив, объект), у массива общая форма элементов. Ответ подходит, если:

1. у каждого значения тип из набора;
2. у объекта нет лишних полей и есть все обязательные;
3. строки по путям из `enums` взяты из перечня;
4. объект по пути из `variants` подходит под форму своего вида, а вид известен.

Порядок полей и сами значения (имена, номера, время) не сверяются.

## Общее

- Время в UTC, ISO 8601 (`2026-10-14T09:40:00Z`). Сайт показывает время сообщений по часам человека, время собеседований по Москве (D-089).
- `seq`: номер сообщения внутри переписки, растёт на 1. По нему листание ленты (`before`, `after`), отметка прочтения (`up_to`) и галочки (`read`).
- `side`: сторона, глазами которой смотрят (`scientist` или `org`). Человек может быть и учёным, и сотрудником организации (D-004), поэтому список переписок просят по стороне.
- Сообщение в адресе правки и удаления называется своим `seq`: `PATCH /api/chats/{id}/messages/{seq}`.
- `events.json`: каждый пример — одно событие живого потока целиком (`id`, `event`, `data`), формы сверяются по виду `event`.
- `links.json`: только новое поле `chat` в ответах откликов и приглашений, остальная часть этих ответов описана их кодом.
- Чужая и несуществующая переписка дают одинаковый 404 `not_found`.
