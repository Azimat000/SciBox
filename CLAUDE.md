# SciBox: frontend и дизайн

В проекте установлены дизайн-скиллы (папка `.claude/skills/`). Правила их использования:

## Какой скилл когда

| Задача | Скилл |
|---|---|
| Новый экран, страница, компонент, редизайн; любая визуальная работа | `impeccable` (основной). Перед первой работой в проекте: `/impeccable init`, он создаст PRODUCT.md и DESIGN.md |
| Лендинг, портфолио, маркетинговая страница с сильным характером | `design-taste-frontend` в паре с `impeccable` |
| Анимации, переходы, «ощущение» интерфейса | `emil-design-eng`, проверка готовых анимаций: `review-animations` |
| Проверка на кривые данные (длинные имена, пустые списки, эмодзи, кириллица) | `break-ui` |
| Финальная проверка кода интерфейса на доступность и UX-правила | `web-design-guidelines` |

Глобально также доступен `frontend-design` (официальный от Anthropic).

## Порядок работы над интерфейсом

1. Если нет PRODUCT.md / DESIGN.md: `/impeccable init`.
2. Строим через `impeccable` (для лендингов добавляем `design-taste-frontend`).
3. `/impeccable audit` и `/impeccable critique`: проверка.
4. `break-ui` на ключевых экранах.
5. `/impeccable polish` перед сдачей.

Хук Impeccable сам проверяет UI-файлы после каждой правки и подсвечивает типичные «ИИ-шные» приёмы (фиолетовые градиенты, градиентный текст, светящиеся тени, Inter, слабый контраст). Его замечания нужно исправлять, а не игнорировать.

## Обновление скиллов

```bash
npx impeccable update
npx skills update -p
```

# Работа срезами и память проекта

Проект строится срезами: один срез = одна сессия. Следующий срез запускается командой `/next-slice` (скилл `.claude/skills/next-slice/`), конкретный: `/next-slice N`.

Память проекта лежит в `docs/` и подгружается хуком SessionStart:

| Файл | Зачем |
|---|---|
| `docs/ROADMAP.md` | Все срезы, статусы, строка `ТЕКУЩИЙ:` |
| `docs/HANDOFF.md` | Записка следующей сессии, перезаписывается в конце каждого среза |
| `docs/DECISIONS.md` | Журнал решений, только дописывается |
| `docs/ARCHITECTURE.md` | Папки, таблицы, API, страницы |
| `docs/DOMAIN.md` | Термины предметной области и их имена в коде |
| `docs/TESTING.md` | Пороги покрытия тестами, критичные зоны, исключения |
| `docs/slices/NN-*.md` | План и отчёт каждого среза |

Правила:
- Решения пользователя из `DECISIONS.md` не пересматривать без его просьбы. Новое решение = новая запись `D-NNN`.
- Если код и документы расходятся, прав код; документы чинятся в том же коммите.
- Покрытие тестами ≥ 90%, в критичных зонах ≥ 97% (`docs/TESTING.md`). Тесты пишутся вместе с кодом; `make test` проверяет пороги и должен быть зелёным.
- В конце каждой сессии, даже незавершённой: обновить память и сделать git-коммит `slice NN: ...`.
- Пользователь не программист: объяснять по-русски и простыми словами, команды давать отдельными блоками `bash`.
